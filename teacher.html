考试数字和手算规则

  • 数字都小于 20，最大素数是 19（老师在 W6、W7 重复了很多遍，说“到复习时你们还会发邮件问计算器为什么算不了大数”）。
  • 计算器没有 mod 键，用除法法：320 mod 9 → 320 ÷ 9 = 35.55…；35 × 9 = 315；320 − 315 = 5。
  • 公式考试不给，必须背：
    • DH：Y = gx mod p；K = (对方的 Y)自己的 x mod p
    • RSA：n = pq；φ = (p−1)(q−1)；e·d mod φ = 1；C = Me mod n；M = Cd mod n
    • 签名：S = Md mod n；验证：Se mod n = M（与加密相反：私钥签，公钥验）
  • 老师说过的扣分点：答案对但没按题目要求写步骤，15 分题只给约 5 分（“我和朋友答案一样，为什么他 A 我 C？”）。每一步都写：公式 → 代入 → 结果，最后验算（解密回原文 / 双方密钥相等）。

DH 必背（W6）

  1. 公开选定素数 p 和生成元 g（题目会给）
  2. 双方各自选私密数（题目会给）
  3. A 算公钥 YA = ga mod p
  4. B 算公钥 YB = gb mod p
  5. 交换公钥
  6. 各自算共享密钥：KA = YBa mod p，KB = YAb mod p，两者相等

可能的追问：私密数泄露会怎样？（攻击者能算出 K，毫无安全性）数字太小会怎样？（会被试出来，实际至少 2048 位）DH 能加密吗？（不能，只交换密钥，之后用 AES 加密）安全基础是什么？（离散对数难题）

RSA 必背（W7）

  • 安全基础：大数分解难题。
  • 选 e 的三个条件：① 1 < e < φ；② e 是素数；③ e 与 p−1、q−1 没有公因子。
  • 为什么 e 不能是 2（往年考题）：除 2 外的素数都是奇数，减 1 后是偶数，2 一定是公因子，不满足第 ③ 条。
  • 求 d 的 k 法：d = (kφ + 1)/e，k = 1, 2, 3… 直到整除。老师建议考试就用这个方法。
  • 老师课上的练习题：p=5, q=11 自选密钥；p=17, q=19, e=5, M=25；p=13, q=23, e=7。

Quiz 高频陷阱（老师点名）

  • CIA 题有约 20 个版本、约 80% 人做错：注意 Access / Consideration 这类拼写陷阱。W3
  • virus 要宿主，worm 不要；人冒充叫 masquerading，服务器/IP 伪造叫 spoofing。W2、W3
  • 没认证不能授权。W5
  • DES = Data Encryption Standard；DES 密钥 56 位（不是 64 位）；AES 分组 128 位，128/192/256 位密钥分别对应 10/12/14 轮。W6
  • “公钥更安全因为有两把钥匙”是错的；没有 unbreakable，也没有 certified encryption；新算法可以用但要谨慎。W8
  • 哈希只提供完整性，不提供认证；证书只认证公钥；SHA 是算法，digest 和 hash value 是输出。W8
  • 验证证书看三件事（“这题以前考过”）：可信 CA（验 CA 签名）、有效期内、未被吊销（查序列号）。W8

Part 1–3 老师口径

  • gray hat：发现漏洞告诉所有者，但会索要钱。W3
  • top-down 总是有效，bottom-up 不行；DLM 第 1–3 层是非技术层（约 75%）；zero trust 下连总裁的设备也要认证。W4
  • identification 是一对多，verification 是一对一；FRR 是 Type I，FAR 是 Type II；3D 人脸约在 90° 内有效。生物识别要 100% 匹配才能取代密码，所以现在只能增强。W5
  • 密码学能提供保密性、完整性、认证和不可否认；不能提供可用性和隐私（机密性 ≠ 隐私）。对称加密适合加密自己的硬盘，公钥加密适合通信，TLS 是两者混合。W5

TLS / Web 安全（W8）

  • HTTP 用 80 端口；HTTPS = HTTP + TLS，用 443 端口。只认证服务器，客户端几乎不认证（太慢、不友好）。
  • SSL 由 Netscape 在 1994 年推出（ElGamal 主导），SSL 3.0 在 1996 年；1999 年 IETF 改名 TLS 1.0；1.1 在 2006 年、1.2 在 2008 年、1.3 在 2018 年 3 月。SSL 3.0 在 2015 年禁用，TLS 1.0/1.1 在 2020 年禁用（因疫情没强制执行）。
  • 公钥至少 2048 位；会话密钥 128 位足够，低于 128 位不安全。
  • TLS 1.3 去掉 RSA 密钥交换：服务器私钥长期不变，被破后历史通信都能解开（前向保密问题），所以改用临时 DH（EDH），每次会话都换参数。RSA 仍可用于签名。
  • TLS 1.3 算法套件从 37 个减到 5 个（不安全的去掉了，管理员也不容易配错），握手更快。
  • Record：分片 → 压缩 → MAC → 加密 → 加头。证书问题由 Alert 报出。Handshake 最复杂。

老师课上的口误 / 课件错误

  • DH 例 p=29、g=2、a=5、b=13：课件写 K = 26，正确是 YB = 14、K = 19。
  • W8 把 TLS 1.3 说成“TLS 3.1”；W7 说 SHA-1 是“168 位”，实际是 160 位；W4 风险例子把 4×3×5 说成“16”，实际是 60。
  • 老师要求 RSA 的 e“必须是素数”，比标准说法（gcd(e, φ) = 1）更严格，考试按老师的写。
