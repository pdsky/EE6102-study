    1HTTP 为什么不安全，HTTPS 加了什么

    你在浏览器（browser）里打开一个网页，浏览器（browser）（客户端（client））用 HTTP 协议（protocol）向服务器（server）发请求，服务器（server）返回网页。HTTP 是一问一答式的请求-响应（request-response）模型，而且无状态（stateless）：每个请求都是独立的，网站靠 cookie 记住你是谁（所以模块 1 说 cookie 记录太多信息时会变成“间谍（espionage）”）。常见请求方法：GET 取数据，POST 提交数据，PUT 更新，DELETE 删除，HEAD 只取头部。

    问题在于：HTTP 是明文（plaintext）的。课件 P5-3 列出了它面临的威胁（threat），正好对上 CIA 和认证（authentication）：

    威胁（threat）具体表现
    Integrity 完整性数据在传输途中被修改、插入内容
    Confidentiality 机密性网络上被窃听（eavesdropping）；服务器（server）上的数据被偷
    Authentication 认证冒充（masquerading）网站、伪造（forgery）数据
    Denial of serviceWeb 服务器（server）被黑、被打瘫

    HTTPS = HTTP + TLS

    HTTPHTTPS
    端口（port）80443
    加密（encryption）无，明文（plaintext）TLS/SSL 加密（encryption）
    认证（authentication）无验证服务器（server）身份（证书（certificate））
    完整性（integrity）数据可被修改数据不能被篡改（tampering）
    速度略快略慢（要先做 TLS 握手（handshake））
    类比

    HTTP 像寄明信片：邮递员、分拣员谁都能看，甚至能改上面的字。HTTPS 像把信装进上锁的保险袋，而且袋子上有收件方的防伪印章。

    课件 P5-6 说：如果你今天网购过、叫过 Grab、用过 WhatsApp 或 Zoom、刷过 YouTube、查过邮件，或者见过地址栏里的小锁，你就已经用过 SSL/TLS 了。网页和邮件是 99% 成功入侵（intrusion）的关键入口，所以 Web 安全格外重要。

    HTTPS 默认使用哪个端口（port）？

    HTTP 用 80，HTTPS 用 443（22 是 SSH）。

    老师课上强调 · W8

    HTTP 用 80 端口（port）、不加密（without encryption）；HTTPS 用 443 端口（port）。按协议（protocol）客户端（client）也可以认证（authentication），但几乎从不这样做：每个用户都要买证书（certificate），速度慢、不好用。所以只有服务器（server）必须有证书（certificate）。

    2SSL/TLS 的来历与分层结构

    历史（P5-8～P5-10）

    时间事件
    1994Netscape 内部设计 SSL；SSLv1 在发布会上就被观众当场破解
    1994–95SSLv2 随 Navigator 发布，但有中间人攻击（man-in-the-middle attack (MITM)）漏洞（vulnerability）
    1996SSLv3，Netscape 和密码学家（cryptographer） Paul Kocher 设计，公开征求意见
    1999IETF 接手，把 SSL 3.0 改名为 TLS 1.0（可以看作 SSL 3.1）
    2006 / 2008TLS 1.1；TLS 1.2（支持 AES、SHA-256，至今仍广泛使用）
    2015SSL 3.0 被禁用（POODLE 攻击），SSL 正式淘汰
    2018TLS 1.3 定稿：握手（handshake）更快、前向保密（forward secrecy）、去掉弱算法（weak algorithm）
    2020TLS 1.0 和 1.1 被弃用

    很多人还习惯说“SSL”，但现在实际用的都是 TLS。

    老师课上强调 · W8
    • SSL 由 Netscape 在 1994 年推出（ElGamal 主导），SSL 3.0 在 1996 年；1999 年交给 IETF，改名 TLS 1.0；TLS 1.1 在 2006 年、1.2 在 2008 年、1.3 在 2018 年 3 月。
    • SSL 3.0 在 2015 年禁用，TLS 1.0/1.1 在 2020 年禁用。原计划 2020 年底全部改用 1.3，但因疫情没有强制执行。
    • 老师用 SSL Labs 演示：微信、Facebook、Google 还开着 1.0/1.1，评分 B（为了用户量和广告收入）；Microsoft、NTU 关掉了，评分 A+。

    SSL 的目标

    机密性（confidentiality）和完整性（integrity）（靠加密（encryption）），以及认证（authentication）（用数字证书（digital certificate）认证服务器（authentication server），认证（authentication）客户端（client）的情况很少见）。它内置在所有主流浏览器（browser）和服务器（server）里，开箱即用（样题 Q5-5：True）。

    两层协议（P5-12）

    • Session（会话）：客户端（client）和服务器（server）之间的一种关联，由握手协议（handshake protocol）建立，定义了一组安全参数（security parameters），可以被多个连接共享；
    • Connection（连接）：一条端到端的可靠安全通道（secure channel），每个连接都属于某个会话（session）。

    Record 协议（protocol）怎么处理数据（P5-14）

    应用数据（application data） → ① Fragment 分片（fragmentation） → ② Compress 压缩 → ③ Add MAC 加消息认证码 → ④ Encrypt 加密（encryption） → ⑤ 加 SSL 记录头（record header）

    MAC 保证完整性（integrity），加密（encryption）保证机密性（confidentiality）（样题 Q5-3：记录协议（record protocol）提供 message integrity 和 confidentiality）。为什么先压缩再加密（encryption）？因为密文（ciphertext）看起来是随机的，压缩不了。

    另外两个小协议（protocol）

    • Change Cipher Spec：非常简单，只做一件事：把“待定”（pending）的参数切换成“当前”（current），也就是正式启用协商好的加密套件（cipher suite）；
    • Alert：向对方发送告警（样题 Q5-4），每条 2 字节（byte）：一个字节（byte）表示 fatal 或 warning，一个字节（byte）是告警代码（alert code），比如 bad record MAC、handshake failure、bad certificate、certificate expired、certificate revoked。
    老师课上强调 · W8

    证书（certificate）出问题（过期、被吊销（revocation）、未知 CA、不支持的证书（certificate））时由 Alert 协议（protocol）报警，还包括坏的 MAC、解压失败（decompression failure）、握手失败（handshake failure）等。四个子协议（sub-protocol）里最复杂的是 Handshake。

    密钥长度（P5-11）

    SSL/TLS 用两种密钥（key）：公私钥（public-private key pair）建议 2048 位（512 位弱，1024 位也能被破解）；会话密钥（session key）每次连接时生成，一般 40–256 位，低于 128 位就不安全。如果浏览器（browser）支持 256 位而服务器（server）只支持 128 位，连接按 128 位建立。会话密钥（session key）可以比公钥（public key）短，因为它被破解只影响一次会话（session），而且能减轻服务器（server）负担。

    SSL 记录协议（record protocol）为连接提供的两项服务是消息完整性（message integrity）和什么？（样题 Q5-3）

    记录协议（record protocol）负责“加 MAC（完整性（integrity））+ 加密（encryption）（机密性（confidentiality））”。认证（authentication）是握手协议（handshake protocol）做的事。

    老师课上强调 · W8

    公钥（RSA/DH）：512 位很弱，1024 位能被破，至少 2048 位。会话密钥（session key）：128 位就够了，低于 128 位不安全，浏览器（browser）最高支持 256 位。

    3一次 TLS 握手（handshake）：最复杂的部分

    握手协议（handshake protocol）是 SSL/TLS 最复杂的部分（样题 Q5-1）。它要完成三件事：双方互相认证（authentication）、协商加密（encryption）和 MAC 算法、协商出密钥（key）。其实就是模块 4 的混合系统（hybrid system）在真实世界里的样子。

    经典 TLS 握手（RSA 密钥交换（key exchange），P5-17）

    ① ClientHello（客户端 → 服务器（server））

    “你好，我想建立安全连接。我支持这些算法组合：……”这份算法组合的列表就是 cipher suite（密码套件）（样题 Q5-2）。一个套件包括：密钥交换算法（key exchange algorithm） + 加密算法（encryption algorithm） + 哈希（hash）/MAC 算法，例如 RSA + AES-128 + SHA-256。

    ② ServerHello（服务器 → 客户端（client））

    “好的，我们就用这个套件。”服务器（server）从客户端（client）的列表里选一个。

    ③ Certificate（服务器（server） → 客户端（client））

    服务器（server）发来自己的数字证书（digital certificate），里面有它的公钥（public key）。客户端（client）按模块 4 的三步验证证书（certificate）：CA 签名（signature）、有效期（validity period）、吊销状态（revocation status）。

    ④ ServerHelloDone

    “我这边说完了。”

    ⑤ ClientKeyExchange（客户端 → 服务器（server））

    客户端随机生成一把对称会话密钥（symmetric session key），用服务器（server）的公钥（public key）加密（encryption）后发过去。服务器（server）用自己的私钥（private key）解开，现在双方都有了同一把会话密钥（session key），Eve 没有。

    ⑥ ChangeCipherSpec

    客户端（client）把选定的加密套件（cipher suite）从“待定”切换为“启用”。

    ⑦ Finished

    客户端（client）表示握手（handshake）结束。从此进入正常通信阶段，所有数据都用对称会话密钥（symmetric session key）加密（encryption），由记录协议（record protocol）负责。

    把模块 4 串起来

    证书（certificate）（认证服务器（authentication server））+ 公钥加密（public-key encryption）（安全地送出会话密钥（session key））+ 对称加密（symmetric encryption）（快速加密（encryption）数据）+ MAC/哈希（hash）（完整性（integrity））。一次握手（handshake）把整章密码学（cryptography）都用上了。

    深入一步：密钥（key）是怎么一步步算出来的

    上面第 ⑤ 步说“客户端（client）生成会话密钥（session key）”，严格来说过程是这样的：

    1. ClientHello 和 ServerHello 里，双方各自带了一个随机数（Client Random、Server Random），明文（plaintext）传输；
    2. 客户端（client）生成一个 pre-master secret（预主密钥），用服务器（server）公钥加密（public-key encryption）后发出，只有服务器（server）能解开；
    3. 双方用同一个公式算出 master secret（主密钥） = 函数(pre-master secret, Client Random, Server Random)；
    4. 再从主密钥（master secret）里切分出 4 把具体的钥匙：
    钥匙用途
    客户端（client） → 服务器（server）的加密密钥（encryption key）Record 加密（encryption）（机密性（confidentiality））
    服务器（server） → 客户端（client）的加密密钥（encryption key）Record 加密（encryption）
    客户端（client） → 服务器（server）的 MAC 密钥（key）Record 加 MAC（完整性（integrity））
    服务器（server） → 客户端（client）的 MAC 密钥（key）Record 加 MAC

    Finished 消息：检查握手（handshake）有没有被动过手脚

    第 ⑦ 步的 Finished 不只是说“我完了”。客户端（client）把到目前为止双方交换的所有握手（handshake）消息放在一起，用主密钥（master secret）算出一个校验值（check value）（本质上是一个 MAC），加密（encryption）后发出。服务器（server）自己也算一遍：一致，说明每一步都没被中间人（man-in-the-middle）篡改（tampering）（比如没人偷偷把 cipher suite 换成更弱的）；不一致，就发 Alert（handshake failure），中断连接。服务器（server）随后也回一组 ChangeCipherSpec + Finished。

    MAC 到底在哪个部分

    MAC 不属于某一个单独的步骤，它贯穿整个过程：

    阶段MAC 的角色
    Handshake ① ②选定 MAC 算法：cipher suite 里的最后一段，例如 TLS_RSA_WITH_AES_128_CBC_SHA256（依次是密钥交换（key exchange）、加密算法（encryption algorithm）、MAC/哈希算法（hash algorithm））
    Handshake ⑤生成 MAC 密钥（key）：从主密钥（master secret）推导出来
    Handshake ⑦ Finished用 MAC 式的校验值（check value）保护握手（handshake）过程本身
    Record 协议（protocol）（之后每一条数据）真正使用 MAC：分片（fragmentation） → 压缩 → 加 MAC → 加密（encryption） → 加记录头（record header）
    一句话

    握手（handshake）负责“定好用哪种 MAC、生成 MAC 密钥（key）”，Record 负责“给每条数据加上 MAC”。所以样题 Q5-3 说 Record 协议（protocol）提供的是 integrity（靠 MAC）和 confidentiality（靠加密（encryption））；authentication 是握手（handshake）负责的（验证证书（certificate））。

    为什么用 MAC，而不是普通哈希（hash）

    普通哈希（hash）谁都能算：Eve 改了数据，可以顺手重算一个新哈希（hash）附上，接收方发现不了。MAC 是带密钥的哈希（keyed hash）：必须知道 MAC 密钥（key）才能算出正确的值，而这把密钥（key）是握手（handshake）时双方私下推导的，Eve 不知道，所以她改了数据也伪造（forgery）不出正确的 MAC。

    类比

    普通哈希（hash）像谁都能盖的普通印章；MAC 像只有你们两人才有的私章。

    TLS 1.3 的变化（只考概念）

    TLS 1.3 不再用 RSA 加密（encryption） pre-master secret，改用 ephemeral DH（见下一节）；MAC 和加密（encryption）合并成一体（AEAD，例如 AES-GCM），完整性（integrity）仍然有，只是不再单独做“加 MAC”这一步。考试按课件的 TLS 1.2 流程回答即可。

    TLS 中，给每条应用数据（application data）加上 MAC 的是哪个协议（protocol）？

    握手（handshake）只负责选定 MAC 算法、生成 MAC 密钥（key）；真正给每条数据加 MAC 的是 Record 协议（protocol）。

    客户端在 ClientHello 里列出的“自己支持的密码算法（cipher）组合”叫什么？

    Cipher suite（样题 Q5-2）。服务器在 ServerHello 里从中选一个。

    4TLS 1.3：为什么去掉了 RSA 密钥交换（key exchange）

    TLS 有两种交换密钥（key）的方式（P5-18～P5-20）：

    1. RSA 密钥交换（key exchange）：上一节那种，客户端（client）决定会话密钥（session key），用服务器（server）公钥加密（public-key encryption）后发出；
    2. Diffie-Hellman 密钥协商（key agreement）：双方各自生成密钥对（key pair），交换公开部分，各自算出同一个值（pre-master secret）。服务器（server）用数字签名（digital signature）保证交换没被篡改（tampering）。如果每次连接都换一对新的密钥（key），就叫 ephemeral（临时的）DH。

    RSA 方式的致命问题：没有前向保密（forward secrecy）

    一个故事

    Eve 没法破解你和银行的通信，于是她先全部录下来存着。三年后，银行服务器（server）被黑，RSA 私钥泄露（private key exposure）。Eve 拿出三年前的录音，用这把私钥（private key）解开当年加密（encryption）的会话密钥（session key），你过去三年的所有通信全部被解密（decryption）。

    这就是课件说的 “RSA mode … is not forward secret”。前向保密（Forward Secrecy / PFS）的意思是：即使长期私钥（long-term private key）日后泄露（leak），过去的会话（session）也依然安全。ephemeral DH 能做到这一点，因为每次会话（session）的密钥（key）都是临时生成、用完就扔的，私钥泄露（private key exposure）也推不出当年的会话密钥（session key）。

    所以 TLS 1.3 去掉了 RSA 密钥交换（key exchange），只保留 ephemeral Diffie-Hellman。RSA 仍可以在 TLS 1.3 里用于签名（signature）（另外两种签名算法（signature algorithm）是 ECDSA 和 EdDSA）。

    老师课上强调 · W8

    老师的讲法：RSA 密钥交换（key exchange）下，服务器（server）的私钥（private key）长期不变，几十亿用户共用同一把。攻击者（attacker）先把密文（ciphertext）录下来，有朝一日破了这把私钥（private key），所有历史通信都能解开。固定参数的 DH 也有同样的问题，所以 TLS 1.3 用临时（ephemeral）DH：每次会话（session）都重新选数字，最坏情况也只泄露（leak）一个客户的一次会话（session）。RSA 仍可用于签名（signature）。

    TLS 1.3 的其他改进（P5-21、P5-26、P5-27）

    • 支持的密码套件（cipher suite）从 37 个减到 5 个，客户端（client）可以直接猜对方用哪种，并提前发出自己的密钥份额（key share）；
    • 握手（handshake）往返从 2 次减到 1 次（1-RTT），更快；
    • 去掉了已知有漏洞（vulnerability）的旧算法：DES、3DES、MD5、RC4、SHA-1、RSA 密钥交换（key exchange）；
    • 更强的加密（AES、ChaCha20）；
    • 协议（protocol）更简单，管理员（administrator）更不容易配置出错，而这正是 TLS 1.2 的主要问题；
    • 取消了对 SSL 的向后兼容（backward compatibility）。
    老师课上强调 · W8

    算法套件（cipher suite）从 37 个减到 5 个，去掉了 DES、3DES、SHA-1、MD5。研究显示服务器（server）出问题多半是管理员（administrator）配错算法，选项少了就不容易配错。握手（handshake）更短更快，回访同一服务器（server）还能复用参数。

    HeartbleedOpenSSL 漏洞（vulnerability），会泄露（leak）内存给 OpenSSL 打补丁（patching）
    DROWN利用配置不当的服务器（server）上的 SSLv2禁用 SSLv2 和弱密码套件（weak cipher suite）

    服务器（server）端：只用 TLS 1.2/1.3、强密码套件（strong cipher suite）、开启 PFS、开启 HSTS（强制 HTTPS）、用 OCSP Stapling 检查证书（certificate）、及时更新 OpenSSL。客户端（client）：验证证书、用证书固定（certificate pinning）防中间人（man-in-the-middle）、在浏览器（browser）里禁用弱协议（weak protocol）。另外要选有信誉的 CA，保管好私钥（private key）。

    TLS 1.3 为什么去掉了 RSA 密钥交换（key exchange）？

    RSA 在 TLS 1.3 里仍可用于签名（signature），被去掉的只是“用 RSA 加密（encryption）会话密钥（session key）”这种交换方式。

    课件逐页详解：TLS 1.3 密钥交换（key exchange）与握手（handshake） P5-18～P5-29、P5-39

    RSA 密钥交换（P5-18）

    TLS 是一个混合密码系统（hybrid cryptosystem）：先用公钥密码（public-key cryptography）让双方安全地拿到同一把密钥（key），再用这把密钥（key）加密（encryption）数据。在 RSA 密钥交换（key exchange）里，共享秘密（shared secret）由客户端（client）决定：客户端（client）从服务器（server）证书（certificate）里取出公钥（public key），用它加密（encryption）共享秘密（shared secret）后发给服务器（server）。

    Diffie-Hellman 密钥协商（P5-19）

    1. 客户端（client）和服务器（server）各自生成一对公私钥（public-private key pair）（基于公开的素数（prime number）和生成元（generator））；
    2. 把自己的公开份额（key share）发给对方；
    3. 每一方用“对方的公开份额 + 自己的私钥（private key）”算出同一个值，这就是 pre-master secret（和模块 4 的 DH 计算完全一样）；
    4. 服务器（server）对这次交换做数字签名（digital signature），证明交换没被篡改（tampering）；
    5. 如果每次连接都换一对新密钥（key），就叫 ephemeral（临时）DH。

    TLS 1.3 的握手（handshake）只要三步（P5-21）

    TLS 1.3 握手（handshake）（1-RTT）

    ① Client Hello：TLS 1.3 把支持的密码套件（cipher suite）从 37 个减到 5 个，客户端（client）可以直接猜服务器（server）会用哪种密钥协商（key agreement）方式，并在第一条消息里就附上自己的 key share，不用像 1.2 那样先等服务器（server）回话。

    ② Server Hello：服务器回复 Server Hello，同时发来证书（certificate）和自己的 key share。此时服务器已经能算出会话密钥（session key），最后发出 server Finished。

    ③ Client Finished：客户端验证证书（certificate），用两份 key share 算出自己的那份会话密钥（session key），然后发出 Finished。握手（handshake）完成，只用了一个往返。

    密钥（key）用 Ephemeral Diffie-Hellman（EDH / DHE）生成；允许的签名算法（signature algorithm）有三种：RSA（只用于签名（signature））、ECDSA、EdDSA。

    为什么 TLS 1.3 更安全（P5-26）

    TLS 1.2 只要配置正确就是安全的，问题是很多网站配置错了。1.3 直接删掉了有已知漏洞（vulnerability）的旧功能：3DES、DES、MD5、RC4、SHA-1 等。协议（protocol）简单了，管理员（administrator）犯错的机会就少了。

    版本状态要点
    SSL 2.0已淘汰加密（encryption）很弱
    SSL 3.0已弃用受 POODLE 攻击
    TLS 1.0已弃用易受降级攻击（downgrade attack）

    课件 P5-39 再补三条：选可靠的 CA（证书（certificate）只和签发它的 CA 一样可信）；保护好私钥（private key）（公钥（public key）可以广泛分发，私钥（private key）要尽可能安全地保管）；使用 TLS 1.3（TLS 1.2 目前用得最多，但 1.3 通过 ephemeral DH 为所有会话（session）提供前向保密（forward secrecy），更快也更安全）。

    5SSL 的局限与 SET

    SSL/TLS 做不到什么（P5-30）

    • 会拖慢服务器（server）；只保护传输中的数据，不保护数据库（database）里的数据；
    • 不能认证（authentication）电脑前真正操作的人，不能认证（authentication）网店老板，不能认证（authentication）真正的消费者；
    • 不能防止有人用偷来的信用卡（credit card）网购；
    • 证书（certificate）要花钱；它是两方协议（protocol）。

    SET：专门为刷卡支付（card payment）设计的协议（protocol）

    1996 年，MasterCard、Visa、Microsoft、IBM、Netscape 等一起设计了 SET（Secure Electronic Transaction），专门保护在开放网络上的银行卡支付（card payment）。它不是一个支付系统，而是一套安全协议（protocol）和格式。

    SSL/TLSSET
    目的加密（encryption）交换数据电商支付（e-commerce payment）
    参与方两方（浏览器（browser）和服务器（server））多方：持卡人（cardholder）、商家（merchant）、银行、支付网关（payment gateway）
    认证（authentication）主要认证服务器（authentication server），不太强所有参与方都有数字证书（digital certificate），认证（authentication）很强
    加密（encryption）对象信道（channel）消息
    商家欺诈（merchant fraud）风险（risk）有，客户把卡号交给了商家（merchant）小，商家（merchant）看不到卡号，卡号交给支付网关（payment gateway）
    客户欺诈（customer fraud）风险（risk）有，客户事后可以拒付（chargeback）小，客户要对支付指令（payment instruction）数字签名（digital signature），不能抵赖（repudiation）
    出了问题谁负责商家（merchant）支付网关（payment gateway）
    实际使用非常广泛几乎没人用，因为银行、商家（merchant）、客户都要装专门的软件

    SET 用到的密码学（cryptography）：对称加密（symmetric encryption）保证机密性（confidentiality），RSA 公钥（public key）做授权（authorization），哈希（hash）保证完整性（integrity）。课件的几个问答：SET 会取代 SSL 吗？不会，两者除了都用密码学（cryptography）和证书（certificate），没有技术上的相似之处。SSL 对电商（e-commerce）够用吗？不够，但没有别的选择。SSL 下商家（merchant）知道客户是谁吗？不知道。

    关于 SET 和 SSL，哪项正确？

    SSL 才是两方协议（two-party protocol）；SET 几乎没人用。

    课件逐页详解：SET 的组成与交易流程 P5-31～P5-38

    SET 的几个关键点（P5-31、P5-33）

    • SET 为卡支付（card payment）中的所有参与者建模：持卡人（cardholder）、商家（merchant）、银行，以及它们之间的信任关系和数字签名（digital signature）的法律含义；
    • 为交易中的每一方提供密码学（cryptography）身份认证（authentication），也就是多方安全（multiparty security）；
    • 加密（encryption）的是消息，而不是信道（channel）；
    • 每个持卡人（cardholder）都会被发一个数字签名（digital signature），它加上会说 SET 协议（protocol）的软件，就组成了 SET 电子钱包（electronic wallet）；
    • SET 的消息和传统银行网络多年来使用的消息基本一样，SET 只是让它们能在不安全的开放互联网（Internet）上传输；
    • SSL 只在两台电脑之间建立安全连接，SET 则定义了银行、商家（merchant）、持卡人（cardholder）之间所有必要的通信；
    • 对商家（merchant）：持卡人（cardholder）事后不能说“不是我买的”，银行有证据；对持卡人（cardholder）：能确认商家（merchant）是合法的。

    一笔 SET 交易的 10 步（P5-34）

    1. 客户开户；
    2. 客户收到一张证书（certificate）；
    3. 商家（merchant）也有自己的证书（certificate）；
    4. 客户下单；
    5. 验证商家（merchant）身份；
    6. 发送订单和支付信息；
    7. 商家（merchant）请求支付授权（payment authorization）；
    8. 商家（merchant）确认订单；
    9. 商家（merchant）提供商品或服务；
    10. 商家（merchant）请求付款。

    SET 用到的密码学（P5-33、P5-36）

    目标用什么
    机密性 Confidentiality对称密钥加密（symmetric key encryption）
    授权 Authorization公钥密码（public-key cryptography） RSA
    完整性 Integrity哈希（hash）
    认证 Authentication所有参与方都用数字证书（digital certificate）认证

    SET 的优点：商家（merchant）看不到客户的账户信息（保护金融隐私（financial privacy））；它是完整的刷卡支付（card payment）系统，包括支付传输、确认和查询。SET 的缺点：银行网络、商家（merchant）和消费者电脑上都必须装相应的软件，这也是它几乎没人用的原因。

    SET vs SSL 的根本区别（P5-37）

    SSL 不能提供不可抵赖性（non-repudiation），而且只做服务器（server）端认证（authentication）；SET 用数字证书（digital certificate）同时认证（authentication）持卡人（cardholder）和商家（merchant），所以付款很难被否认，商家（merchant）也能确定收到的订单没被改过。

    6防火墙（firewall）基础：网络的门卫

    Firewall 是一种网络安全设备（network security device）或软件，根据组织事先制定的安全策略（security policy），监控和过滤进出网络的流量（traffic）。它是内部私有网络和公共互联网（Internet）之间的那道墙，目的就是放行无害流量（traffic）、挡住危险流量（traffic）（样题 Q5-8）。

    • 防火墙（firewall）可以是单台计算机，也可以是两台或更多系统协同完成（样题 Q5-6：True）；
    • 硬件防火墙（hardware firewall）：保护整个网络，部署在路由器（router）层面，一般更贵、更难配置；
    • 软件防火墙（software firewall）：保护单台电脑，便宜、易配置。

    进入网络的流量（traffic）叫 ingress，离开网络的叫 egress。课件有一句很重要的话：防火墙（firewall）只丢弃能被证明是攻击的包，所以总有一些“看起来正常”的攻击包（attack packet）能溜进来，防火墙（firewall）不是万能的。

    类比：房子与房间（P5-51）

    把 IP 地址（IP address）想成房子，端口（port）号想成房子里的房间。只有可信的人（源地址（source address））能进这栋房子（目的地址（destination address）），进来以后还要看身份决定能进哪些房间（目的端口（destination port））：主人哪个房间都能进，孩子和客人只能进某些房间。

    规则从上到下逐条检查，第一条完全匹配的规则说了算，后面的不再看。最后一条通常是 “Any Any Any → Deny”（默认拒绝（default deny））。

    规则表（rule table）就是课件上的那三条。改一改数据包（packet）的源地址（source address）、目的地址（destination address）和端口（port），看它命中哪一条。

    IP 地址（IP address）欺骗（deception）

    入侵者（intruder）从外部发送数据包（packet），却把源地址（source address）填成内部主机（internal host）的地址，冒充（masquerading）自己人，这叫 IP address spoofing（样题 Q5-10）。好在外部接口（external interface）上不可能出现合法的“内部源地址（source address）”，包过滤防火墙（packet filtering firewall）很容易识别并丢弃这种包。

    个人防火墙（P5-53）

    保护单台联网电脑的软件（样题 Q5-11 把 personal 误印成了 personnel）。能做：阻止黑客（hacker）访问电脑、保护个人信息、拦截弹窗和某些 cookie、决定哪些程序能上网。不能做：防邮件病毒（virus）（要靠杀毒软件（antivirus software））；装好以后就不管（规则和软件都需要定期更新）。

    防火墙（firewall）的优缺点（P5-54）

    优点：阻止未授权访问（unauthorized access）、过滤流量（traffic）、记录日志（log）并告警（alert）。缺点：降低网络速度、配置复杂、防不了内部人员（insider）、能被隧道（tunneling）和加密流量（encrypted traffic）绕过、挡不住社会工程（social engineering）和零日漏洞（zero-day vulnerability）。所以样题 Q5-12“防火墙（firewall）能防御绕过它的攻击”是 False。

    “The firewall can protect against attacks that bypass the firewall.”

    FALSE（样题 Q5-12）。流量（traffic）不经过它，它就管不着：内鬼（insider）、U 盘（USB drive）、私接的热点（hotspot）都能绕过。

    课件逐页详解：网络安全控制（network security controls）与防火墙（firewall）工作方式 P5-40～P5-54

    网络安全控制（P5-40）

    网络是一组用有线或无线方式连起来的设备。网络安全控制（network security controls）指用来加强网络安全（cyber security）的各种措施：访问控制（access control）、认证（authentication）、授权（authorization）、密码学（cryptography）、Web 安全、安全策略（security policy）等。防火墙（firewall）是其中最常见的一种。

    防火墙（firewall）怎么挡住蠕虫（worm）和黑客（P5-45）

    你向互联网（Internet）请求东西时，防火墙（firewall）会假装是它自己发出的请求，而不是你的电脑。互联网（Internet）根本看不到你的电脑，蠕虫（worm）和黑客（hacker）能探测、攻击的就只剩防火墙（firewall），而防火墙（firewall）只是一个“笨盒子”（dumb box），没什么可以被利用的。

    防火墙（firewall）的基本运作（P5-47～P5-49）

    1. 合法主机发送正常的包，攻击者（attacker）发送攻击包（attack packet）；
    2. 进入站点的叫 ingress（入站），离开站点的叫 egress（出站）；
    3. 防火墙（firewall）丢弃并记录能够证明是攻击的包；
    4. 防火墙（firewall）只在能证明是攻击时才丢包，所以有些“无法证明”的攻击包（attack packet）会穿过防火墙（firewall）。

    软件防火墙（software firewall）怎么工作（P5-44）

    它检查到达防火墙（firewall）任何一侧的每一个“包”（进入你电脑的，或从你电脑出去的），决定让它通过还是拦下。

    防火墙策略（P5-50）

    防火墙按一组预先定义的规则，即防火墙策略（firewall policies），过滤进出的流量（traffic），以保护私有网络和单台机器免受互联网（Internet）威胁（threat）。一边是可信的内网（trusted internal network），一边是不可信的互联网（un-trusted Internet）。

    7防火墙（firewall）的类型：看得越深越安全，也越慢

    类型怎么工作特点
    Packet filtering 包过滤逐个检查包头（packet header）：源 IP、目的 IP、端口（port），按规则放行或丢弃（样题 Q5-9）快、便宜；无状态（stateless），不记得之前的包，也不看更高层的内容（样题 Q5-7：True）
    Stateful inspection（SPI） 状态检测除了包头（packet header），还用状态表（state table）记录每条连接（IP、端口（port）、序列号（serial number）），只放行“内网（internal network）主动发起的连接”的回包比包过滤（packet filtering）更安全，资源消耗更多；维护状态表（state table）可能被 DoS 拖垮；如今几乎所有边界防火墙（perimeter firewall）都用它
    Proxy / Application gateway 代理作为中间人（man-in-the-middle）：用户向代理（proxy）请求，代理（proxy）检查请求合法后替你去取，再把结果返回能看懂完整的应用协议（protocol），最安全，日志审计（logging and auditing）方便；但最慢
    NGFW 下一代防火墙传统功能 + 入侵防御（IPS）+ 深度包检测（DPI）+ 应用识别（application identification）更先进，也更贵；“下一代”没有统一定义
    Cloud firewall部署在云上，保护远程用户（Firewall-as-a-Service）弹性好，但依赖第三方
    WAF专门保护 Web 应用防 SQL 注入（SQL injection）、XSS

    包过滤（packet filtering）又分三种：static（按固定规则匹配（rule matching））、dynamic（能根据突发事件临时更新规则）、stateful（即 SPI）。

    类比：小区门卫
    • 包过滤（packet filtering）：只看车牌，名单上有就放行，不记得这辆车刚才有没有出去过；
    • SPI：有一本登记簿，“这辆车是业主刚开出去的，现在回来，放行”；陌生车想主动进来就拦下；
    • 代理（proxy）：外人一律不准进，你要什么，门卫替你出去拿回来，还会检查东西里面有没有问题。

    包过滤防火墙（P5-57）

    成本低，对网络性能影响小。它有三种子类型：

    • Static filtering（静态过滤）：包符合规（compliance）则就放行或丢弃；
    • Dynamic filtering（动态过滤）：能理解协议（protocol）怎么工作，根据包头（packet header）信息对突发事件作出反应，更新或新建规则；
    • Stateful inspection（状态检测）：用状态表（state table）跟踪内部和外部系统之间的每一条连接。

    静态包过滤（P5-58）

    • 最早的防火墙（firewall）过滤机制；
    • 一次只看一个包，孤立地看；只看部分网络层（network layer）和传输层（transport layer）头部；
    • 所以很多攻击它挡不住，但能挡住伪造（forgery） IP 地址（IP address）的包；
    • 如今不再作为边界防火墙（perimeter firewall）的主要过滤机制，但可以作为主边界防火墙（primary perimeter firewall）上的辅助过滤（secondary filtering）。

    状态包检测 SPI（P5-59）

    • 检查和包过滤（packet filtering）一样的包信息，此外还记录 TCP 连接的信息；
    • 用状态表（state table）跟踪内部和外部系统之间建立的每一条连接，记录哪台机器在什么时候发了什么包；
    • 能判断一个包是不是属于内网（internal network）发起的合法会话（legitimate session）；
    • 状态表（state table）记录每条活动连接（active connection）的 IP 地址（IP address）、端口（port）和序列号（serial number）；
    • 因此只放行“作为内网（internal network）发起连接的回复”的入站（ingress） TCP 包；
    • 主要缺点：管理和核对状态表（state table）需要额外处理，可能让系统被 DoS 攻击拖垮。

    连接的状态（P5-60）

    一条连接分为三个阶段：建立（opening）→ 通信中（ongoing communication）→ 关闭（closing）。不同阶段面临不同的攻击，所以 SPI 对不同状态使用不同的过滤规则。

    为什么 SPI 成了主流（P5-64）

    理由课件原意
    Low cost 成本低绝大多数包都不是“建立连接”的包，处理起来简单便宜；建立连接的包处理成本更高，但很少
    Safety 安全除了应用层攻击（application-layer attack），其他攻击通常过不了 SPI；需要时 SPI 还能叠加其他过滤方式
    Dominance 主导地位安全性高加上成本低，使它极其流行，如今几乎所有主边界防火墙（primary perimeter firewall）都用 SPI

    应用网关（application gateway） / 代理服务器（P5-65）

    • 通常装在一台专用计算机（dedicated computer）上，也叫代理服务器（proxy server）；
    • 它常被放在网络中不安全的区域（例如 DMZ），面对的风险（risk）更高；这样暴露在外的是代理服务器（proxy server），而不是 Web 服务器（server）；
    • 代理（proxy）后面还可以再加过滤路由器（filtering router）；
    • 配置成 Web 代理（proxy）的网关（gateway）不放行 FTP、Gopher、Telnet 等其他流量（traffic）；
    • 它能完整理解协议（protocol）：用户向代理（proxy）请求服务，代理（proxy）验证请求合法后代为执行，再把结果返回给用户；
    • 比包过滤（packet filtering）更安全：只需要审查少数几个允许的应用，而且容易记录和审计（audit）所有进入的流量（traffic）。

    8防火墙架构（firewall architecture）：从单个路由器（router）到 DMZ

    选哪种架构，取决于网络的目标、组织的实施能力和预算。课件介绍了四种（P5-69～P5-75）：

    1. Packet filtering router：用连接互联网（Internet）的路由器做包过滤（packet filtering），是第一代防火墙（first-generation firewall）。缺点：缺少审计（audit），也没有强认证（strong authentication）；
    2. Screened host（单主机）：路由器（router）先预筛一遍，后面再接一台专门的防火墙（firewall）（比如应用代理（application proxy））。这台主机叫 bastion host（堡垒主机）或牺牲主机（sacrificial host），会直接面对外部攻击，必须加固（hardening）。它被攻破，整个防线就没了；
    3. Dual-homed host（双宿主机）：防火墙（firewall）有两块网卡（network interface card (NIC)），一块接互联网（Internet），一块接内网（internal network），还能做 NAT（内网（internal network）用私有地址（private address））。比 screened host 更安全，但仍是单点故障（single point of failure）；
    4. Screened subnet（屏蔽子网，带 DMZ）：用两台过滤路由器（filtering router）或防火墙（firewall），中间夹一块 DMZ（非军事区），对外提供服务的 Web 服务器（server）放在 DMZ 里。

    它的优点：入侵者（intruder）要过三层防御（three layers of defense）；外部路由器（exterior router）只向互联网（Internet）宣告 DMZ 的存在，内网（internal network）对互联网（Internet）不可见；内部路由器（interior router）只向内网（internal network）宣告 DMZ，所以内网（internal network）主机也无法直接建立通往互联网（Internet）的路由。

    “边界（perimeter）已死”？防火墙（firewall）还需要吗（P5-79～P5-82）

    传统思路是“内网（internal network）可信、外网（external network）不可信”，防火墙（firewall）守在边界（perimeter）上。但云计算（cloud computing）、远程办公（remote work）和 BYOD、零信任（zero trust）、越来越多的加密流量（encrypted traffic）、钓鱼（phishing）和内鬼（insider）这类复杂威胁（sophisticated threat），让“固定边界（perimeter）”逐渐瓦解。课件的结论是：边界（perimeter）没有消失，只是移动了，从固定位置变成跟着用户、设备和数据走的、以身份为基础的边界（perimeter）。防火墙（firewall）仍然重要，但不再是唯一防线，要和下一代防火墙（next-generation firewall (NGFW)）、云防火墙（cloud firewall）、网络分段（network segmentation）、零信任（zero trust）一起用。

    推荐做法（P5-84）

    • 允许内网（internal network）流量（traffic）出站（egress）；防火墙（firewall）设备本身不能从公网（public network）直接访问；
    • SMTP 邮件通过配置好的邮件网关（mail gateway）转发；拒绝所有 ICMP；阻止外部对内部服务器（server）的 telnet；
    • 对外提供 Web 服务时，用代理（proxy）或 DMZ，不让 HTTP 流量（traffic）直接进入内网（internal network）。

    永恒的权衡：和外界沟通的程度 vs 安全级别。安全规则一旦和业务冲突，安全往往会让步，因为组织宁可接受潜在风险（risk），也不愿接受确定的业务中断。

    用两台过滤路由器（filtering router）、中间放置面向公众服务器（server）的架构是？

    两台路由器（router） + DMZ = screened subnet。

    选架构看三件事（P5-69）

    1. 网络的目标；
    2. 组织开发和实施这种架构的能力；
    3. 可用的预算。

    四种架构的课件要点

    架构课件要点
    Packet filtering router（P5-69、P5-70）大多数联网组织都有一台路由器作为通往互联网（Internet）的接口，很多路由器（router）可以配置成拒绝组织不允许的包。它是第一代防火墙（first-generation firewall）。缺点：缺少审计（audit），也没有强认证（strong authentication）
    Screened host（P5-71、P5-72）包过滤路由器（packet filtering router）加上一台独立的专用防火墙（firewall）（例如应用代理（application proxy））。路由器（router）先预筛，减轻内部代理（proxy）的负担。这台单独的主机叫 bastion host（堡垒主机）或 sacrificial host（牺牲主机），会成为外部攻击的目标，必须彻底加固（hardening）。结构简单，但这台防火墙（firewall）一旦被攻破就全线失守
    Dual-homed host（P5-71、P5-73）防火墙（firewall）有两块网卡（network interface card (NIC)）：一块连互联网（Internet），一块连内网（internal network）。可以做 NAT：对外用公网（public network） IP，内网（internal network）用 NAT 分配的本地地址（local address）。比 screened host 更安全，但仍是单点故障（single point of failure）
    Screened subnet（P5-74、P5-75）用两台防火墙（firewall）形成 DMZ，把面向公众的服务（如 Web 服务器（server））放在里面，在内部系统和互联网（Internet）之间再加一层隔离。三层防御（three layers of defense）；外部路由器（exterior router）只向互联网（Internet）宣告屏蔽子网（screened subnet），内网（internal network）对互联网（Internet）不可见；内部路由器（interior router）只向内网（internal network）宣告屏蔽子网（screened subnet），内网（internal network）主机无法直接建立到互联网（Internet）的路由

    课件 P5-74 的结论：防火墙（firewall）对网络安全（cyber security）至关重要，但必须配合 IDS、终端防护（endpoint protection）等措施；组织应按安全需求、网络规模和预算选择防火墙（firewall）类型和架构；单靠防火墙（firewall）不能防住所有威胁（threat），需要分层的安全方法。

    “边界（perimeter）已死”的五个原因（P5-79、P5-80）

    1. 云计算（cloud computing）：数据存放在 AWS、Azure、Google Cloud 等云环境里，员工从任何地方访问，绕开了传统防火墙（firewall）；
    2. 远程办公（remote work）与 BYOD：员工用个人设备和家庭网络访问公司数据，传统防火墙（firewall）无法对远程用户执行策略（policy）；
    3. 零信任模型（zero trust model）：“永不信任，总是验证”取代了基于边界（perimeter）的信任；访问权限（access rights）基于身份、上下文和最小权限（least privilege），而不是网络位置；
    4. 加密流量（encrypted traffic）增加：很多攻击本身就用加密（encryption），防火墙（firewall）难以检查；攻击者（attacker）用 SSL/TLS 隧道（tunneling）绕过传统防火墙（firewall）；
    5. 更复杂的威胁（threat）：恶意软件（malware）和黑客（hacker）通过钓鱼（phishing）、内部人员（insider）、被盗凭证（stolen credentials）进入网络内部，基于边界（perimeter）的防火墙（firewall）就失效了。

    我们还需要防火墙（firewall）吗（P5-81、P5-82）

    需要，但单靠它不够。现代做法包括：

    • 下一代防火墙（NGFW）：深度包检测（DPI）、入侵防御（IPS）、应用层过滤（application-layer filtering）、基于机器学习的威胁检测（threat detection）；还能检查加密流量（encrypted traffic）、监控用户行为，从而执行零信任（zero trust）原则；
    • 云防火墙（FWaaS）：不需要本地硬件就能保护云上工作负载和远程用户，例如 Zscaler、Palo Alto Prisma、Cloudflare Gateway；
    • 网络分段（network segmentation）：不再只靠一道边界防火墙（perimeter firewall），而是把网络分成多个隔离的小区域，攻击者（attacker）攻破一段也不能在网内自由移动。

    结论：边界（perimeter）没有消失，而是变得动态和分散；防火墙（firewall）在演进而不是消亡，要和零信任（zero trust）、终端安全（endpoint security）、云安全（cloud security）结合起来。

    选择防火墙（firewall）时要问的问题（P5-83）

    • 哪种防火墙（firewall）技术在防护功能和成本之间最适合本组织？
    • 基础价格包含哪些功能？哪些要额外付费？所有成本都清楚了吗？
    • 安装和配置难不难？有没有熟练的技术人员能做好？
    • 它能否适应组织网络的增长？

    配置和管理防火墙（P5-83）

    每台防火墙（firewall）都有自己的一套配置规则；一个小错误就可能把它变成网络的瓶颈（choke point）。当安全规则和业务表现冲突时，安全往往会输，因为组织宁可承受“可能的风险（risk）”，也不愿接受“肯定的业务中断”。

    9入侵检测（IDS）与入侵防御（IPS）

    防火墙（firewall）是门卫，IDS 是监控摄像头：它监视网络或系统的活动，发现可疑行为就告警（alert）。它的基本假设是：入侵者（intruder）的行为和合法用户（genuine user）不同，而且这种差异可以量化（样题 Q5-13：True）。

    优点：早期发现威胁（threat）、实时监控（real-time monitoring）、提供取证（forensics）日志（log）、帮助满足合规（compliance）。缺点：会有误报（false positive）和漏报（false negative），消耗计算资源，而且只告警（alert）、不拦截。

    按“看哪里”分：HIDS vs NIDS

    HIDS 主机型（host-based）NIDS 网络型（network-based）
    监视什么单台主机上的活动：日志（log）、审计记录（audit trail）、进出该主机的流量（traffic）（样题 Q5-15）网段（network segment）的流量（traffic），分析网络层（network layer）、传输层（transport layer）、应用层（application layer）协议（protocol）（样题 Q5-16）
    告警（alert）线索登录失败、非正常时段登录、权限提升（privilege escalation）、新增用户账户（user account）流量（traffic）里出现已知的攻击特征（attack signature）
    优点能看解密（decryption）后的数据；误报（false positive）少；可以针对具体操作系统（operating system）和应用少量设备就能覆盖整个网段（network segment）；部署和维护成本低；能关联多台机器上的攻击
    缺点每台要监视的机器都要装，拥有成本高，占用本机资源流量（traffic）加密（encryption）后就失效；看不到主机内部的活动

    HIDS 还分被动的（只分析、告警（alert））和主动的（能执行脚本、终止进程）；现代的 HIDS 常被称为 HIPS，集成了主机防火墙（host firewall）、行为和特征检测（signature-based detection）、恶意软件防护（malware protection）。

    按“怎么判断”分：特征检测（signature-based detection） vs 异常检测（anomaly detection）

    Signature-based 特征检测（signature-based detection）Anomaly-based 异常检测（anomaly detection）
    别名knowledge-based 基于知识statistical / behavior-based 基于统计（statistics-based）或行为
    原理拿流量（traffic）和已知攻击（known attack）模式（特征库（signature database））比对，像杀毒软件（antivirus software）的病毒库（virus database）先收集合法用户（genuine user）在一段时间内的正常行为，建立基线（baseline）；之后定期采样比较，超出阈值（clipping level）就告警（alert）
    擅长已知攻击（known attack），误报（false positive）少能发现新型攻击
    缺点特征库（signature database）要不断更新；对新攻击会漏报（false negative）误报多（false positive）；细微变化可能察觉不到
    类比

    特征检测（signature-based detection）像拿着通缉令认人：照片上的人一眼就能认出，没上过通缉令的新罪犯认不出来。异常检测（anomaly detection）像小区保安对住户很熟，“这人平时不这样”就会起疑心，能发现陌生的坏人，但也常误会正常住户。

    • Q5-18“收集合法用户（genuine user）在一段时间内的行为数据”是 Anomaly detection，没有争议。

    IDS 入侵检测（intrusion detection）IPS 入侵防御（intrusion prevention）
    做什么检测并告警（alert）检测并拦截

    蜜罐 Honeypot（P5-95）

    故意设置一台诱饵系统（decoy system），看起来像真的（比如假的客户计费系统），还故意留下漏洞（vulnerability），吸引攻击者（attacker）进来。用途：观察攻击者（attacker）的手法，改进真实网络的防护；或者把攻击者（attacker）从真实目标引开。局限：它发现不了真实系统上的入侵（intrusion），也不一定能查出攻击者（attacker）是谁。

    公司的流量（traffic）大部分走 HTTPS 加密（encryption），想检查解密（decryption）后的内容，应该更依赖？

    NIDS 遇到加密流量（encrypted traffic）就“失明”；HIDS 在主机上，能看到解密（decryption）后的数据。

    一种全新的攻击（零日（zero-day）），哪种检测方法更有可能发现它？

    零日攻击（zero-day attack）不在特征库（signature database）里；但它的行为偏离了正常基线（baseline），异常检测（anomaly detection）有机会发现，代价是误报（false positive）多。

    IDS 的优缺点（P5-86）

    优点缺点
    早期发现威胁（threat）：在造成重大损失前发现可疑活动
    实时监控（real-time monitoring）：持续分析系统和网络活动
    取证分析（forensic analysis）：留下攻击尝试的日志（log）和记录
    执行安全策略（security policy）：帮助满足合规（compliance）要求    		误报（false positive）：异常检测（anomaly detection）可能把正常活动当成威胁（threat）
    漏报（false negative）：特征检测（signature-based detection）可能漏掉新出现的威胁（threat）
    资源消耗大：处理大量流量（traffic）需要算力（computing power）
    不会主动防护（proactive protection）：只检测和告警（alert），不拦截（IPS 才会）

    IDS 的分类（P5-87）

    按部署位置分为 HIDS 和 NIDS；按检测方法分为 signature-based（依赖预定义的攻击和流量（traffic）模式，即“特征”）和 anomaly-based（heuristic，启发式）（监控活动，把它分类为“正常”或“异常”）。

    NIDS 的工作方式（P5-87～P5-89）

    • NIDS 是解析网络流量（network traffic）的引擎；
    • 它抓取全部网络流量（network traffic），与一组预先分类的攻击特征（attack signature）比对；
    • 一旦在包里发现特征，就启动保护动作，阻止并记录攻击；
    • 部署容易，不需要大改网络；
    • 优点：覆盖整个网络需要的设备少；部署、维护和升级成本通常较低；能看到全部网络流量（network traffic），可以关联多台系统上的攻击；
    • 缺点：流量（traffic）加密（encryption）后就无效；不知道主机自身发生了什么。

    HIDS 的工作方式（P5-90～P5-92）

    • 只检查某一台主机上的活动：日志（log）、审计记录（audit trail）、进出该主机的流量（traffic）；可以实时检查，也可以定期检查；
    • 会触发告警（alert）的迹象：登录失败、非正常时段登录、权限提升（privilege escalation）、新增用户账户（user account）；
    • 优点：可以针对具体操作系统（operating system）和具体应用；能降低误报（false positive）率；能检查解密（decryption）之后的数据；能判断一次告警（alert）会对系统造成什么影响；
    • 缺点：要监视的每台机器都得处理信息；拥有和维护成本可能很高；占用本机资源；
    • Passive HIDS（被动）：观察、分析活动并发出告警（alert）；
    • Active HIDS（主动）：能力相同，还能作出反应，比如运行脚本、终止进程；
    • 现代 HIDS 常被称为 HIPS（主机入侵防御系统），用三样东西来阻止攻击：集成的系统防火墙（firewall）、基于行为（behavior-based）和特征的 IDS、恶意软件（malware）检测与防护。

    课件 P5-91 的示意：Host IDS 检查主机上存储的文件，有变化就通知管理员（administrator）；Network IDS 检查网络上的包，发现异常模式就通知管理员（administrator）。

    入侵防御系统 IPS（P5-94）

    IPS 是一种主动的安全技术，实时检测并拦截恶意活动；IDS 只检测和告警（alert）。IPS 常集成在下一代防火墙（NGFW）里。

    蜜罐（P5-95）

    • 一台牺牲性的计算机系统，像诱饵一样吸引网络攻击（cyberattack）；
    • 它模仿黑客（hacker）的目标，利用入侵（intrusion）尝试来了解攻击者（attacker）的手法，或者把攻击者（attacker）从其他目标引开；
    • 看起来像真实系统，有应用和数据，比如模仿公司的客户账单系统（这是想偷信用卡（credit card）号的罪犯常攻击的目标）；
    • 黑客（hacker）进来后就可以被追踪，他们的行为能为加强真实网络提供线索；
    • 蜜罐（honeypot）会故意留下安全漏洞（security vulnerability），让攻击者（attacker）觉得有吸引力；
    • 局限：发现不了真实系统里的入侵（intrusion），也不一定能查出攻击者（attacker）是谁。

    网络攻击（cyberattack）带来的影响（P5-97）

    每年有超过一半的企业成为网络攻击（cyberattack）目标。影响包括四类：

    影响具体表现
    Financial 财务从几万到几百万美元不等，还不包括恢复成本
    Productivity 生产力时间就是金钱：修复社会工程（social engineering）攻击和处理损失要花大量时间，影响 IT 团队、普通员工，最终影响盈利
    Operational disruption 运营中断影响会传导到整个供应链（supply chain）和服务交付，造成物流延误
    Reputational damage 声誉损失客户不再觉得安全，信任很难重新建立

    10本章小结

    一页纸总结
    • HTTP 明文（plaintext）、无状态（stateless）、端口（port） 80；HTTPS = HTTP + TLS、端口（port） 443，提供机密性（confidentiality）、完整性（integrity）和服务器认证（server authentication）。
    • SSL 由 Netscape 设计 → 1999 年改名 TLS 1.0 → 2018 年 TLS 1.3；SSL 在 2015 年淘汰。
    • 分层：Handshake、Change Cipher Spec、Alert 在上，Record 在下（机密性（confidentiality） + 完整性（integrity）：分片（fragmentation） → 压缩 → MAC → 加密（encryption） → 加头）。
    • 握手（handshake）最复杂：ClientHello（列出 cipher suites）→ ServerHello（选一个）→ Certificate → ServerHelloDone → ClientKeyExchange（用服务器（server）公钥加密（public-key encryption）会话密钥（session key））→ ChangeCipherSpec → Finished。
    • TLS 1.3：去掉 RSA 密钥交换（key exchange）（没有前向保密（forward secrecy）），只用 ephemeral DH；1-RTT；去掉 DES、3DES、MD5、RC4、SHA-1。会话密钥（session key） ≥ 128 位。
    • SSL 是两方协议（two-party protocol），用得多；SET 是多方协议（multi-party protocol），所有参与方都有证书（certificate）、商家（merchant）看不到卡号，但几乎没人用。
    • 防火墙（firewall）：只挡能证明是攻击的包；防不了绕过它的攻击和内鬼（insider）。包过滤（packet filtering）无状态（stateless）最快，SPI 有状态表（state table），代理（proxy）最安全最慢。
    • 规则从上到下，第一条匹配即生效，最后一条默认拒绝（default deny）；吞吐量（throughput） pps = 带宽（bandwidth） ÷ (包大小（packet size） × 8)。
    • 架构：包过滤路由器（packet filtering router） → screened host（堡垒主机（bastion host））→ dual-homed（双网卡（network interface card (NIC)） + NAT）→ screened subnet（两台路由器（router） + DMZ）。
    • HIDS 看单机、能看解密（decryption）后的数据；NIDS 看网段（network segment）、怕加密（encryption）。Signature 认已知攻击（known attack）（漏报（false negative）新攻击），Anomaly 认正常基线（baseline）（能发现新攻击，误报（false positive）多）。IDS 只告警（alert），IPS 会拦截；蜜罐（honeypot）是诱饵。
