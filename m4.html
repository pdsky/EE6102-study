    1密码学（cryptography）要解决什么问题

    密码学（cryptography）的故事里永远有三个人：Alice 要给 Bob 发消息，Eve（eavesdropper，窃听者）在中间偷听。互联网（Internet）就是一个“人人都能偷听”的地方：你的消息要经过路由器（router）、Wi-Fi、运营商……任何一环都可能有 Eve。

    密码学（cryptography，来自希腊语 kryptós“隐藏的” + gráphein“书写”）就是用数学把消息变成别人看不懂的样子，只有拥有正确钥匙的人才能还原。

    基本术语（P4-5）

    Plaintext 明文
    原始的、能读懂的消息，例如 HELLO
    Ciphertext 密文
    加密（encryption）后的输出，看起来像乱码，例如 XJ#94@K
    Cipher 密码算法
    加密（encryption）和解密（decryption）用的数学步骤（算法）
    Key 密钥
    一串字符或比特，和算法配合使用。算法可以公开，密钥必须保密
    Encryption 加密
    明文（plaintext） → 密文（ciphertext），记作 E(M) = C
    Decryption 解密
    密文（ciphertext） → 明文（plaintext），记作 D(C) = M
    Cryptanalysis 密码分析
    试图破解密码（password cracking）系统，例如暴力破解（brute force）、字典攻击（dictionary attack）、彩虹表攻击（rainbow table attack）
    易错点

    样题 Q4-1：“The process of converting from plaintext to cipher text is known as deciphering or decryption.” 答案是 No。明文（plaintext） → 密文（ciphertext）是加密（encryption），说反了。

    密码学（cryptography）能提供什么（P4-16）

    • Confidentiality 机密性：只有授权（authorization）的人能读（靠加密（encryption））；
    • Integrity 完整性：收到的就是发出的（靠哈希（hash））；
    • Authentication 认证：确认消息来自谁（靠数字签名（digital signature））；
    • Non-repudiation 不可否认：发送者不能抵赖（靠数字签名（digital signature））。
    老师课上强调 · W5

    密码学（cryptography）能提供保密性（confidentiality）、完整性（integrity）、认证（authentication）和不可否认（non-repudiation），但不能提供可用性（availability）和隐私（privacy）。机密性（confidentiality）不等于隐私（privacy）。对称加密（symmetric encryption）适合加密（encryption）你自己的硬盘，公钥加密（public-key encryption）适合和别人通信，TLS 是两者混合。

    三大类密码（P4-11），本章的路线图

    类别钥匙数量代表主要用途本章位置
    Symmetric 对称1 把（双方共享）DES、3DES、AES、RC4大量数据加密（encryption）第 4 节
    Asymmetric 非对称（公钥（public key））2 把（公钥（public key） + 私钥（private key））RSA、Diffie-Hellman、ElGamal、ECC密钥交换（key exchange）、数字签名（digital signature）第 5–9 节
    Hashing 哈希不用钥匙SHA-2、SHA-3、MD5（已淘汰）完整性（integrity）、存储密码（password）第 10 节

    2从凯撒密码（Caesar cipher）开始：替换、置换与“钥匙”的意义

    最古老的密码学（cryptography）用在军事和政治上（Q&A Q21：最早用于在传递途中隐藏军事和政治机密）。凯撒大帝用过一个简单的办法：每个字母往后移 3 位，A→D、B→E……这就是替换密码（substitution）：把每个字母换成另一个。

    凯撒密码（Caesar cipher）机

    “算法”是“字母往后移 k 位”，“密钥（key）”就是 k。改改密钥（key）看看效果，再想想：如果 Eve 知道算法，她最多要试几次就能破解？

    答案是只需试 25 次，因为只有 25 种有意义的移位。这说明了密码学（cryptography）的第一条原理：

    核心思想

    安全不能靠“算法保密”，要靠“密钥空间（key space）足够大”。DES 的设计要求里就写着：“The security of the algorithm must depend on the key”，并且算法细节必须公开（P4-21）。算法不变，换一把钥匙，结果就完全不同（P4-13）。

    另外两类古典思路：置换密码（transposition），字母不变、打乱顺序（比如把 HELLO 写成 OLLEH）；乘积密码（product），把替换、置换、模运算（modular arithmetic）组合起来反复做。现代的 DES 和 AES 本质上就是“多轮替换 + 置换”的乘积密码（product cipher）。

    密钥长度（key length）：每多 1 位，难度翻倍

    钥匙是一串比特（0 和 1），n 位的钥匙就有 2n 种可能（P4-14）：

    • 8 位：28 = 256 种，平均试 128 次就能猜中，不用电脑都能破；
    • 56 位（DES）：256 种。每秒试 100 万个，需要约 2285 年；
    • 64 位：约 58.5 万年；128 位：约 1025 年。

    但现实比理论危险：电脑远比每秒 100 万次快，黑客（hacker）还能用几百万台僵尸机（zombie computers）并行计算。1998 年 EFF 造了一台专用机器，56 小时就破解了 DES。所以：安全 = 算法强度（algorithm strength） + 密钥长度（key length）。

    密钥（key）从 56 位增加到 58 位，暴力破解（brute force）的时间大约变成原来的多少倍？

    每多 1 位翻一倍，多 2 位就是 2 × 2 = 4 倍。这就是“指数（exponent）”。

    3对称加密（symmetric encryption）：一把钥匙锁门也开门

    Symmetric（secret-key）cryptography：加密（encryption）和解密（decryption）用同一把钥匙（样题 Q4-2）。发送方用密钥（key） K 把明文（plaintext） M 变成密文（ciphertext） C，接收方用同一个 K 把 C 还原成 M：

    加密（encryption）：C = EK(M)　　解密（decryption）：M = DK(C) = DK(EK(M))

    算法（E 和 D）是公开的，所有人都知道 AES 怎么运算；安全性只靠密钥（key）保密。这就是第 2 节说的“钥匙才是关键”：只要 Eve 拿不到 K，她在信道（channel）上截到再多密文（ciphertext）也没用。

    一个能手算的例子：一个字节（byte）的 XOR 加密（encryption）

    真实的 AES 太复杂，没法手算，但它的核心思想可以用最简单的对称（symmetric）运算 XOR（异或）体会：两位相同得 0，不同得 1。XOR 有个神奇性质：同一个 K 异或两次，就回到原样，所以同一把钥匙既能加密（encryption）也能解密（decryption）。

    例：Alice 用密钥（key） K = 10110011 加密（encryption）字母 “H”

    第一步：把明文（plaintext）变成二进制。字母 H 的 ASCII 码是 72，写成 8 位二进制：

    M = H = 01001000

    Alice 和 Bob 事先约好（安全地共享了）密钥（key） K = 10110011。

    第二步：加密（encryption），C = M ⊕ K（逐位异或）。

    M = 0 1 0 0 1 0 0 0⊕ K = 1 0 1 1 0 0 1 1 C = 1 1 1 1 1 0 1 1（十六进制 FB，已经看不出是 H 了）

    Alice 把 C 发给 Bob。Eve 在网上截到的只有 11111011。

    第三步：解密（decryption），M = C ⊕ K（用同一把钥匙再异或一次）。

    C = 1 1 1 1 1 0 1 1⊕ K = 1 0 1 1 0 0 1 1 M = 0 1 0 0 1 0 0 0 = H ✓

    Bob 拿回了 H。如果 Eve 不知道 K，11111011 可能对应任何一个字母；但只要 K 泄露（leak），她也能一步解开。这正说明对称加密（symmetric encryption）的全部安全都押在“钥匙别丢”上。

    类比

    一个带密码（password）锁的箱子：你锁上寄出去，对方用同一个密码（password）打开。锁很结实（算法很强），但问题是：你怎么把密码（password）安全地告诉对方？打电话可能被窃听（eavesdropping），写信可能被拆开，当面告诉又太麻烦。这就是对称加密（symmetric encryption）最大的难题：密钥分发（key distribution）。

    最大难题：密钥分发（key distribution）和扩展性（scalability）

    对称加密（symmetric encryption）要求双方事先拥有同一把密钥（key），而且这把钥匙不能通过要保护的那条不安全信道（channel）直接发过去（否则 Eve 也会拿到）。人一多，问题更严重：每两个人之间都需要一把独立的钥匙，否则 A 和 B 的悄悄话 C 也能解开。n 个人两两通信需要

    密钥（key）数 = n(n − 1) / 2
    人数 n需要的密钥（key）数算式
    464 × 3 ÷ 2
    104510 × 9 ÷ 2
    1004,950100 × 99 ÷ 2
    1,000499,5001000 × 999 ÷ 2

    人数翻 10 倍，钥匙数大约翻 100 倍，每把钥匙还要生成、安全送达、保存、定期更换。现实中的三种解决办法：

    • 线下交付：当面给、专人押送。安全，但慢、贵，人多了根本不可行。
    • 可信第三方 / 密钥分发（key distribution）中心（KDC）：每人只和中心共享一把钥匙，由中心临时发会话密钥（session key）（如 Kerberos）。但中心一旦被攻破，全部失守。
    • 公钥（public key）技术：用 Diffie-Hellman 或 RSA 在公开网络上安全地约定或传送对称密钥（symmetric key）（第 5、7 节），再用对称加密（symmetric encryption）传大量数据，这就是第 9 节的混合系统（hybrid system）。HTTPS 就是这么做的。

    优点与缺点（P4-19）

    优点缺点
    快：运算简单，通常比公钥加密（public-key encryption）快几百到上千倍，适合加密（encryption）大量数据密钥分发（key distribution）难：双方必须事先安全地共享密钥（shared key）（最大缺点，样题 Q4-7）
    密钥（key）短：128 位 AES 密钥（key）就已经很安全扩展性（scalability）差：n 个人需要 n(n−1)/2 把钥匙
    实现简单、应用广泛：硬件（CPU 的 AES 指令）普遍支持不能提供不可否认性（non-repudiation）：双方钥匙一样，B 收到消息后无法向第三方证明是 A 发的（A 可以说“是 B 自己写的”）

    生活中哪里在用：HTTPS 握手（handshake）完成后，网页内容其实是用 AES 加密（encryption）传输的；家里 Wi-Fi 的 WPA2/WPA3 密码（password）就是一把共享的对称密钥（symmetric key）；Windows BitLocker、苹果 FileVault 用 AES 加密（encryption）整个硬盘；带密码（password）的压缩包也是对称加密（symmetric encryption）。

    易错点
    • 对称加密（symmetric encryption） = secret-key（共享秘密（shared secret）钥匙），只有一把钥匙。不要和公钥（public key）体系里的 private key（私钥）混淆：private key 是非对称加密（asymmetric encryption）里只有自己知道的那一把。
    • “公钥加密（public-key encryption）有两把钥匙所以更安全”是错的（老师 W8 点名）。两者安全性取决于密钥长度（key length）和算法，不取决于钥匙数量；实际中两者一起用。
    • 对称加密（symmetric encryption）只解决机密性（confidentiality）（配合 GCM 等模式还能保证完整性（integrity）），解决不了“证明是谁发的”。

    一个 25 人的团队，每两个人之间都要用对称加密（symmetric encryption）单独通信，一共需要多少把密钥（key）？

    n(n−1)/2 = 25 × 24 ÷ 2 = 300。50 是把每人算两把（公钥（public key）体系才是 2n），625 是 n² 忘了去重和除 2。

    分组密码（block cipher） vs 流密码（P4-15）

    对称加密（symmetric encryption）按“一次处理多少数据”分成两大类：

    Block cipher 分组密码：把消息切成固定大小的块，每块用算法和密钥（key）整体加密（encryption）（样题 Q4-3）。例子：DES（每块 64 位 = 8 字节（byte））、AES（每块 128 位 = 16 字节（byte））。

    例：用 AES 加密（encryption）一条 40 字节（byte）的消息

    AES 每块 16 字节（byte）。40 ÷ 16 = 2.5，所以要切成 3 块：第 1 块 16 字节（byte）、第 2 块 16 字节（byte）、第 3 块只有 8 字节（byte），不够一整块，要填充（padding） 8 个字节（byte）补满 16 字节（byte）再加密（encryption）。如果换成 DES（每块 8 字节（byte）），40 ÷ 8 = 5，正好 5 块，不用填充。每一块都用同一把密钥（key）、经过多轮替换和置换（第 4 节细讲），输出同样大小的密文（ciphertext）块。

    Stream cipher 流密码：不分块，而是用密钥生成（key generation）一串和消息一样长的伪随机密钥流（keystream），一次加密（encryption）一位（或一个字节（byte））：每个明文（plaintext）字节（byte）和对应的密钥（key）流字节（byte）做 XOR。例子：RC4（老算法，已不安全）、ChaCha20（TLS 1.3 在用）。

    例：用流密码（stream cipher）加密（encryption） “HI”

    密钥生成（key generation）的密钥（key）流前两个字节（byte）是 10110011、01011100，逐字节（byte）异或：

    H = 01001000 ⊕ 10110011 = 11111011I = 01001001 ⊕ 01011100 = 00010101

    来一个字节（byte）就加密（encryption）一个字节（byte），不用等凑够 16 字节（byte），也不需要填充。解密（decryption）时 Bob 用同一把密钥生成（key generation）同样的密钥（key）流，再异或一次即可。

    分组密码（block cipher）流密码（stream cipher）
    每次处理一整块（DES 64 位，AES 128 位）一位或一个字节（byte）
    不够长怎么办最后一块要填充不需要填充
    适合场景文件、磁盘、数据库（database）等成块的数据实时通信、语音视频等连续数据流
    例子DES、3DES、AESRC4、ChaCha20
    关键注意要选好工作模式（modes of operation）（下面讲）同一密钥（key）流绝不能重复使用

    RC4 属于哪一类？

    RC4 一次加密（encryption）一个字节（byte），是流密码（stream cipher）。DES、AES 才是分组密码（block cipher）。

    分组密码（block cipher）的工作模式（modes of operation）：ECB 和 CBC

    分组密码（block cipher）只规定了“一块怎么加密（encryption）”，多块之间怎么串起来，由工作模式（modes of operation）决定：

    • ECB（Electronic Codebook，电子密码（password）本）：每块各自独立加密（encryption）。缺点：相同的明文（plaintext）块一定得到相同的密文（ciphertext）块。比如一份工资表里有 100 行都是 “SALARY: 5000.00 ”（正好 16 字节（byte）），加密（encryption）后会出现 100 个一模一样的密文（ciphertext）块，Eve 虽然解不开，却能看出“这些人工资一样”。用 ECB 加密（encryption）一张图片，轮廓甚至还能看出来。
    • CBC（Cipher Block Chaining，密文（ciphertext）分组链接）：每块明文（plaintext）先和上一块的密文（ciphertext）做 XOR 再加密（encryption），第一块和一个随机的初始向量（IV）做 XOR。这样前后块像链条一样连在一起，即使 100 行内容一样，加密（encryption）结果也各不相同，规律被隐藏了。

    用 ECB 模式加密（encryption）一份有很多重复行的文件，主要风险（risk）是什么？

    ECB 每块独立加密（encryption），相同输入 → 相同输出，重复的内容在密文（ciphertext）里一样重复。CBC 通过链接和 IV 解决这个问题。

    4DES、3DES、AES：三代对称加密（symmetric encryption）标准

    上一节讲了对称加密（symmetric encryption）的思想，这一节看具体算法。三代标准一脉相承：DES 是第一个公开的商用标准，被算力（computing power）追上后用 3DES 临时顶替，最后由 AES 接班，沿用至今。

    年份事件

    1976–77IBM 的 Lucifer 修改后成为 DES
    1998EFF 用专用破解机 56 小时穷举出 DES 密钥（key）；1999 年联合分布式计算（distributed computing）缩短到约 22 小时

    DES：第一个商用标准（P4-21～P4-26）

    1973 年 NBS 公开征集方案，IBM 的 Lucifer 经过修改后被采纳，1976–77 年成为 DES（Data Encryption Standard）。

    DES 三个数字（必背）

    分组 64 位，密钥（key） 56 位，16 轮。

    一个 64 位的块在 DES 里怎么走：

    1. 初始置换（IP）：把 64 位按固定表格打乱顺序；
    2. 切成两半：左半 L0、右半 R0，各 32 位；
    3. 16 轮：每一轮用一把由主密钥（master secret）生成的 48 位子密钥（subkey） Ki，按下面的规则更新左右两半（这种结构叫 Feistel 结构）：
      Li = Ri−1Ri = Li−1 ⊕ f(Ri−1, Ki)
      其中 f 函数里有扩展、和子密钥（subkey）异或、查 S 盒（S-box）（替换）、再置换几步。每一轮都在做替换 + 置换，16 轮后明文（plaintext）被彻底打乱；
    4. 最终置换（FP）：IP 的逆操作，输出 64 位密文（ciphertext）。

    解密（decryption）用完全相同的结构，只要把 16 把子密钥（subkey）倒过来用（K16 先用）。这就是 Feistel 结构的好处：加密（encryption）和解密（decryption）可以共用一套硬件。

    易错点

    样题 Q4-5：DES 的密钥（key）多长？答案是 56 位，不是 64 位。64 是分组长度。（输入的密钥（key）其实也是 64 位，但其中 8 位是校验位（parity bits），有效的只有 56 位。）

    老师课上强调 · W6

    “DES 是 Data Encryption Standard，quiz 里有题，有学生选错。”“密钥（key）是 56 位。有的资料写 64 位，那是完全错的：虽然输入 64 位，但 8 位是冗余的，攻击者（attacker）只需要找 56 位。”

    算一算：56 位为什么不够

    56 位密钥（key）一共有 256 ≈ 7.2 × 1016 种。假设每秒能试 109 把：

    7.2 × 1016 ÷ 109 = 7.2 × 107 秒7.2 × 107 ÷ 31,536,000 ≈ 2.3 年（一台机器）

    一台机器要两年多，但用 1,000 台并行就不到一天。1998 年 EFF 的专用破解机花约 25 万美元，56 小时就破解了。这和第 1 章暴力破解（brute force）题是同一个算法：组合数（number of combinations） ÷ 速度，再换算成年。

    争议：IBM 原设计的分组和密钥（key）都是 128 位，被改成了 64 和 56；S 盒（S-box）是在保密条件下设计的，又不给理由，于是有人怀疑 NSA 留了“后门（backdoor）”（trapdoor）。很多专家在 DES 被采纳之前就认为 56 位太短。结局：如今 DES 已经过时，只在老系统和教学里使用。

    DES 被破了怎么办：加密（encryption）两次、三次？

    换一个全新算法需要多年评审，最快的补救办法是把 DES 用好几次，让密钥（key）变长。

    2DES（双重 DES）：用两把密钥（key）连续加密（encryption）两次：

    C = EK2( EK1(M) )　　密钥（key） 2 × 56 = 112 位

    看起来要试 2112 次，实际上会被中间相遇攻击（meet-in-the-middle）破解。假设攻击者（attacker）手上有一对已知的明文（plaintext） M 和密文（ciphertext） C：

    1. 从明文（plaintext）一端：用全部 256 个可能的 K1 加密（encryption） M，把结果存成一张表；
    2. 从密文（ciphertext）一端：用全部 256 个可能的 K2 解密（decryption） C，每算出一个就去表里查；
    3. 两边在“中间”对上了，就同时找到了 K1 和 K2。

    总工作量约 256 + 256 = 257，只比破单 DES 多一倍，远不是 2112（代价是要一张很大的表）。所以 2DES 基本没用。

    3DES（三重 DES）：用 DES 做三次，采用 E-D-E（加密（encryption）-解密（decryption）-加密（encryption））结构：

    加密（encryption）：C = EK3( DK2( EK1(M) ) )解密（decryption）：M = DK1( EK2( DK3(C) ) )
    • 三把不同的钥匙：密钥（key） 3 × 56 = 168 位，受中间相遇攻击（meet-in-the-middle attack）影响，实际强度约 112 位，仍然很安全；
    • 两把钥匙（K1 = K3）：密钥（key） 112 位，也很常用；
    • 中间用“解密（decryption）”的好处：令 K1 = K2 时，前两步互相抵消，3DES 就退化成单 DES，方便和老设备兼容；但要是误用，安全性就只剩单 DES 的水平。

    3DES 的缺点是慢（每块要算三次 DES），分组也仍是 64 位，所以只是过渡方案；NIST 已在 2023 年底停止允许用它加密（encryption）。

    老师课上强调 · W6
    • 2DES 是两把 56 位密钥（key），不是一把 112 位，可以分开破，再加上中间相遇攻击（meet-in-the-middle attack），所以被放弃。
    • 3DES 是 E-D-E 结构：用户给 168 位密钥（key），系统切成三把 56 位子密钥（subkey）。如果 K1 = K2，第一步加密（encryption）和第二步解密（decryption）互相抵消，结果和单 DES 一样，还慢 3 倍。这种情况偶尔会发生，所以 3DES 只是临时方案。

    2DES 用了两把 56 位密钥（key），为什么实际安全性只比单 DES 好一点点？

    攻击者（attacker）从明文（plaintext）和密文（ciphertext）两端同时算、在中间对答案，工作量约 2 × 256 = 257。所以要用 3DES，或直接换 AES。

    AES：现在的金标准（P4-32～P4-40）

    美国政府公开征集 DES 的替代者，经过 5 年严格评选（候选包括 MARS、RC6、Serpent、Twofish 等），评选看重三点：安全性、软硬件上的速度、实现的灵活性。最终选中两位比利时密码学家（cryptographer） Daemen 和 Rijmen 设计的 Rijndael，2001 年成为 AES（Advanced Encryption Standard）。2003 年起美国政府认可它保护机密信息，NSA 也用它加密（encryption）绝密信息。

    AES 怎么加密（encryption）一块：把 128 位（16 字节（byte））的分组排成一个 4 × 4 的字节（byte）方阵，叫“状态”（state）。先和第一把轮密钥（round key）异或一次，然后重复多轮，每轮四步：

    步骤做什么作用
    SubBytes 字节替换每个字节查 S 盒（S-box）换成另一个字节（byte），例如 53（十六进制）→ ED替换，引入非线性（混淆）
    ShiftRows 行移位第 0 行不动，第 1、2、3 行分别循环左移 1、2、3 个字节（byte）置换，把字节（byte）打散到不同列
    MixColumns 列混合每一列的 4 个字节（byte）按固定公式混合成新的 4 个字节（byte）一个字节（byte）变了，整列都跟着变（扩散）
    AddRoundKey 加轮密钥和这一轮的轮密钥（round key）逐位异或把密钥混进来，没有密钥就还原不了

    最后一轮没有列混合（MixColumns）。轮密钥（round key）由主密钥（master secret）“扩展”生成，AES-128 一共要 11 把（开头 1 把 + 10 轮各 1 把）。经过几轮之后，明文（plaintext）只要改 1 位，密文（ciphertext）大约一半的位都会变，这就是雪崩效应（avalanche effect）。

    2128 ≈ 3.4 × 1038 种密钥（key）。就算每秒试 1012 把：

    3.4 × 1038 ÷ 1012 ÷ 31,536,000 ≈ 1.1 × 1019 年

    用在哪：HTTPS（TLS 里最常用的是 AES-GCM）、Wi-Fi（WPA2/WPA3）、VPN、硬盘加密（BitLocker、FileVault）、银行系统。现在的 CPU 都有专门的 AES 指令，加密（encryption）速度可达每秒数 GB。选多长的密钥（key）：一般 AES-128 就够；保护绝密信息或要防范将来的量子计算机（quantum computer），就用 AES-256（量子算法大约能把对称密钥（symmetric key）的强度减半，256 位减半后仍有 128 位）。

    选算法时该信什么（样题 Q4-8～Q4-11 连环题）

    样题有一组连环题，问的是“怎么判断一个加密算法（encryption algorithm）值得信”。答题思路就是本节的历史：DES 用了二十年才被算力（computing power）追上，AES 经过 5 年公开评选、又被全世界攻了二十多年都没破，所以可信。

    • 宣传“牢不可破”（unbreakable）的：多半是夸大，只要算力（computing power）够，任何密钥（key）都能穷举；
    • “认证过的加密”（certified encryption）：课件的观点是没有这种东西；
    • 新算法：可以用，但要谨慎；
    • 反面例子：自己发明、不公开细节的“秘密算法”最不可信，安全不能靠算法保密，只能靠密钥（key）保密。

    5公钥加密（public-key encryption）：一对钥匙，彻底解决“钥匙怎么送”

    第 3 节留下了一个难题：对称加密（symmetric encryption）的双方必须事先共享同一把钥匙，而这把钥匙没法安全地在网上传。1976 年，斯坦福的两位研究者 Diffie 和 Hellman 提出了一个革命性的想法：用两把不同但数学上相关的钥匙（P4-47）。1978 年 Rivest、Shamir、Adleman 又提出了 RSA，让这个想法真正可用。

    • 公钥（public key）：公开给全世界，可以挂在网站上、印在名片上，用来加密（encryption）和验证签名（signature）；
    • 私钥（private key）：只有主人自己知道，用来解密（decryption）和生成签名（signature）。

    规则只有一条：用其中一把加密（encryption）的东西，只有另一把能解开。而且从公钥（public key）推不出私钥（Q&A Q23）。

    类比：挂锁

    Bob 买了很多把打开着的挂锁，发给所有人（这就是公钥（public key）），钥匙只有他自己有（私钥（private key））。Alice 想给 Bob 寄东西，就把东西放进箱子，咔嚓锁上 Bob 的挂锁寄出。路上谁拿到箱子都打不开，连 Alice 自己也打不开了，只有 Bob 能开。钥匙从来不需要寄送，对称加密（symmetric encryption）“钥匙怎么送”的难题就这样解决了。

    为什么“从公钥（public key）推不出私钥（private key）”：单向（one-way）陷门（trapdoor）函数

    公钥算法（public key algorithm）都建立在一种特殊的数学运算上：正着算很容易，倒着算极难，除非你知道一个秘密（陷门（trapdoor））。

    • RSA 用的是大数分解（integer factorization）：算 13 × 17 = 221 一眼就行；但只给你 221，让你找出是哪两个素数（prime number）相乘，就得一个个试。把数字换成 600 多位，正着乘仍是瞬间完成，倒着分解（factorization）用全世界的计算机也要算到宇宙毁灭。公钥（public key）里有那个大数 n，私钥（private key）藏着它的两个因子。
    • Diffie-Hellman、ElGamal 用的是离散对数（discrete logarithm）：算 gx mod p 很快，已知结果反推 x 极难（第 7 节）。
    • ECC 用的是椭圆曲线上的离散对数（discrete logarithm）：同样难，但密钥（key）短得多（第 9 节）。

    一个能手算的例子：Bob 的一对迷你钥匙

    先不管钥匙怎么生成（第 8 节 RSA 会手算全过程），假设 Bob 已经有了一对 RSA 钥匙：

    Bob 的公钥（public key）（公开）：e = 7，n = 33Bob 的私钥（private key）（只有他知道）：d = 3
    例：同一对钥匙的两种用法

    用法一：保密。Alice 要把数字 2 秘密地发给 Bob。她从网上拿到 Bob 的公钥（public key） (7, 33)，加密（encryption）：

    C = Me mod n = 27 mod 33 = 128 mod 33 = 29

    Alice 把 29 发出去。Eve 截到 29，也知道公钥（public key） (7, 33)，但没有 d，解不开。

    Bob 用自己的私钥（private key） d = 3 解密（decryption）：

    M = Cd mod n = 293 mod 33 = 24389 mod 33 = 2 ✓

    全程没有任何秘密在网上传过：Alice 只用了公开的东西，却完成了只有 Bob 能读的加密（encryption）。这就是公钥加密（public-key encryption）的威力。

    用法二：签名（signature）。Bob 要发一个数字 5，并证明是他本人发的。他用自己的私钥（private key）签名（signature）：

    S = Md mod n = 53 mod 33 = 125 mod 33 = 26

    Bob 把消息 5 和签名（signature） 26 一起发出去。

    任何人都能用 Bob 的公钥（public key）验证：

    Se mod n = 267 mod 33 = 5 = 消息 ✓

    算出来正好等于 5，说明签名（signature）一定是用 Bob 的私钥（private key）做的，而私钥（private key）只有 Bob 有。注意：签名（signature）不保密，人人都能验证、都能看到 5；它保证的是“是谁发的”和“没被改过”。

    两种用法：方向正好相反

    万能口诀：谁用谁的哪把钥匙
    目的发送方用接收方用
    保密（只让对方看）接收方的公钥（public key）加密（encryption）自己的私钥（private key）解密（decryption）
    签名（signature）（证明是我发的）自己的私钥（private key）签名（signature）发送方的公钥（public key）验证

    两种一起用：Alice 想让消息既保密、又能证明是她发的，就先用自己的私钥（private key）签名（signature），再用 Bob 的公钥（public key）加密（encryption）。Bob 收到后先用自己的私钥（private key）解密（decryption），再用 Alice 的公钥（public key）验证签名（signature）。整个过程一共用到 4 把钥匙（两人各一对），这正是第 11 节数字签名（digital signature）的基础。

    钥匙双方共享同一把每人一对：公钥（public key）公开，私钥（private key）自留

    代价一：慢。RSA 要对几百位的大数做乘方取模，比 AES 的字节（byte）替换慢得多（在一台普通笔记本上实测，一次 RSA-2048 签名（signature）约 0.44 毫秒，同样的时间 AES 能加密（encryption）约 4.6 MB 数据）。而且 RSA 一次能加密（encryption）的数据长度不能超过 n。所以实际中只用公钥加密（public-key encryption）传一把对称密钥（symmetric key），真正的数据仍用 AES 加密（encryption），这就是第 9 节的混合系统（hybrid system）。

    代价二：要确认公钥（public key）的主人。公钥（public key）是公开的，攻击者（attacker） Mallory 也可以发布一把自己的公钥（public key），谎称“这是 Bob 的”。Alice 一旦用了它，消息就被 Mallory 解开了（中间人攻击（man-in-the-middle attack (MITM)））。所以需要一个可信的第三方给公钥（public key）“盖章”，证明“这把公钥（public key）确实属于 Bob”，这就是后面要讲的数字证书（digital certificate）和 CA。

    各算法能做什么：RSA 既能加密（encryption）也能签名（signature）；Diffie-Hellman 只能交换密钥（key），不能直接加密（encryption）或签名（signature）；DSA 只用于签名（signature）；ECC 是一类方法，有用于密钥交换（key exchange）的 ECDH 和用于签名（signature）的 ECDSA。

    易错点
    • 样题 Q4-12：“非对称加密（asymmetric encryption）只用公钥加密（public-key encryption）和解密（decryption）”是 False，它用一对钥匙。
    • 样题 Q4-13：“非对称加密（asymmetric encryption）能用于保密但不能用于认证（authentication）”是 False，两者都能。
    • 样题 Q4-14：“公钥加密（public-key encryption）比对称加密（symmetric encryption）更安全，因为用两把钥匙”是 False。安全取决于算法强度（algorithm strength）和密钥长度（key length）：128 位 AES 和 3072 位 RSA 强度相当。公钥（public key）解决的是分发问题，不是强度问题。

    Carol 要给 Bob 发一条机密消息，她用哪把钥匙加密（encryption）？（样题 Q4-21）

    保密 → 用接收方的公钥（public key）。A 太含糊（是谁的公钥（public key）？）；C 是签名（signature）的用法。接着样题 Q4-22：Bob 用自己的私钥（private key）解密（decryption）；Q4-24：私钥（private key）由接收方用来解密（decryption）。

    班上 30 个学生都要把加密（encryption）作业交给教授，需要多少把公钥（public key）和私钥（private key）？（样题 Q4-23）

    官方答案是 D。如果只要保密，大家都用教授的公钥加密（public-key encryption），只需教授的 1 对钥匙；如果还要证明作业是哪个学生交的（签名（signature）），每个学生还要有自己的一对钥匙。数量取决于需求，这题考的就是这一点。

    Alice 要给公开的合同签名（signature），让任何人都能确认是她签的。她该用哪把钥匙？

    签名（signature）用发送方自己的私钥（private key），验证用发送方的公钥（public key）。只有 Alice 有自己的私钥（private key），所以能证明是她签的。用接收方公钥（public key）是“保密”的方向；对称密钥（symmetric key）双方都有，没法证明是谁签的。

    6数学准备：模运算（modular arithmetic）（只要会除法就行）

    RSA 和 Diffie-Hellman 都建立在模运算（modular arithmetic）上。别怕，a mod n 就是 a 除以 n 的余数（remainder）。

    类比：钟表

    现在 10 点，再过 5 小时是几点？10 + 5 = 15，钟表上是 3 点。这就是 15 mod 12 = 3。模运算（modular arithmetic）就是“绕圈计数”。

    课件的例子（P4-50）：

    • 15 mod 20 = 15（15 比 20 小，余数（remainder）就是它自己）；
    • 320 mod 9：计算器上 320 ÷ 9 = 35.5555…，取整数部分 35，再算 320 − 35 × 9 = 320 − 315 = 5。课件的方法是用小数部分 0.5555… × 9 = 5，结果一样，但小数误差容易出错，推荐“减去整数倍”的方法。

    模幂（modular exponentiation）：xe mod n 怎么手算

    RSA 要算 181913 mod 2537 这种东西，181913 有 43 位，计算器装不下。诀窍是：每乘一次，就取一次余数（remainder），数字永远不会变大。最快的方法叫平方-乘法（square-and-multiply）：

    例：算 513 mod 23

    第一步：把指数（exponent）写成 2 的幂之和。13 = 8 + 4 + 1（二进制 1101）。所以 513 = 58 × 54 × 51。

    第二步：反复平方，每步取余。

    51 mod 23 = 552 = 25 mod 23 = 254 = (52)2 = 22 = 458 = (54)2 = 42 = 16

    第三步：把需要的几项乘起来，每步取余。

    513 = 58 × 54 × 51 ≡ 16 × 4 × 516 × 4 = 64 mod 23 = 1818 × 5 = 90 mod 23 = 90 − 69 = 21

    答案：513 mod 23 = 21。全程最大的数只有 90。

    7Diffie-Hellman：在大庭广众下约定一个秘密

    问题（Q&A Q30）：Alice 和 Bob 想共用一把对称密钥（symmetric key），但他们只能通过 Eve 能看到一切的信道（channel）说话。怎么才能约定一把 Eve 不知道的钥匙？

    类比：混颜料
    1. 两人公开约定一种公共颜色：黄色（Eve 也知道）；
    2. 各自偷偷选一种秘密颜色：Alice 红，Bob 蓝；
    3. 各自把秘密色混进黄色，把混合色公开发给对方：Alice 发橙色，Bob 发绿色（Eve 看得到）；
    4. 各自把自己的秘密色加进对方发来的混合色：Alice 得到黄 + 蓝 + 红，Bob 得到黄 + 红 + 蓝，完全相同；
    5. Eve 只有黄、橙、绿三种颜色。混合容易，拆分极难，她调不出最终颜色。

    在数学里，“混合”就是模幂运算（modular exponentiation），“拆不开”就是离散对数难题（discrete logarithm problem）。

    算法步骤（P4-53～P4-55）

    步骤A（Alice）B（Bob）Eve 能看到吗

    为什么两边相等？(aXB)XA = aXAXB = (aXA)XB，指数（exponent）相乘的顺序无所谓。

    原根（primitive root）是什么？课件定义：素数（prime number） p 的原根（primitive root），是它的各次幂能生成 1 到 p−1 所有整数的那个数。考试题会直接给出，你不用自己找。

    老师课上强调 · W6

    DH 的要点
    • DH 只用于交换密钥（key），不能加密（encryption）或解密（decryption）消息（P4-51）；
    • 安全性基于离散对数难题（discrete logarithm problem）：已知 g、x、p，求 y = gx mod p 很容易；已知 y、g、p，反求 x 极难（样题 Q4-16：True）；
    • 用于 SSL 的密钥交换（key exchange）；TLS 1.3 只保留了 ephemeral DH（模块 5）；
    • 弱点：DH 本身不验证对方身份，可能被中间人攻击（man-in-the-middle attack (MITM)），所以 TLS 会用签名（signature）保护它。

    8RSA：最常用的公钥（public key）系统，手算全流程

    RSA 以三位 MIT 教授 Rivest、Shamir、Adleman 的姓氏命名，1978 年发表（英国 GCHQ 在 1973 年就秘密发现过），是最广泛使用的公钥（public key）系统（样题 Q4-15、Q4-17）。和 DH 不同，它是完整的系统：密钥生成（key generation） + 加密（encryption） + 解密（decryption） + 签名（signature）都能做。安全性来自大数分解难题（integer factorization problem）：两个大素数（large prime）相乘很容易，把乘积分解（factorization）回去几乎不可能（样题 Q4-20）。

    密钥生成（key generation）五步（P4-67、P4-68）

    用 p = 5、q = 11 生成一对 RSA 钥匙（课件 P4-70～P4-72）

    ① 选两个素数（prime number） p = 5，q = 11（真实系统里是几百位的大素数（large prime））。

    ② 算模数（modulus） n = p × q = 5 × 11 = 55。n 是公开的。

    ③ 算 φ(n) = (p−1)(q−1) = 4 × 10 = 40。φ 必须保密。

    陷阱

    样题 Q4-18 问 p = 5、q = 11 时的 φ，选项里有 55（那是 n），正确答案 40 不在选项里，选 None of the above。Q4-19 问 n，答 55。

    ④ 选公钥（public key） e：要求 1 < e < φ，且 e 和 φ 没有公因子（common factor）（互素（relatively prime））。课件的做法：e 取素数（prime number），检查它和 p−1 = 4、q−1 = 10 有没有公因子（common factor）：

    • e = 2：和 4、10 都有公因子（common factor） 2，✗
    • e = 3：没有公因子（common factor），✓
    • e = 5：和 10 有公因子（common factor） 5，✗
    • e = 7：没有公因子（common factor），✓

    选 e = 3。

    ⑤ 求私钥（private key） d：要满足 e × d ≡ 1 (mod φ)，也就是 e × d = k × φ + 1。课件的方法：d = (k × φ + 1) ÷ e，k 从 1 开始试，直到能整除：

    k = 1：(40 + 1) ÷ 3 = 41 ÷ 3，不能整除 ✗k = 2：(80 + 1) ÷ 3 = 81 ÷ 3 = 27 ✓

    所以 d = 27。验证：3 × 27 = 81 = 2 × 40 + 1 ✓。

    公钥（public key） = (n, e) = (55, 3)，公开给所有人；私钥（private key） = d = 27，自己保管。

    老师课上强调 · W7
    • 选 e 的三个条件（期末要写）：① 1 < e < φ；② e 是素数（prime number）；③ e 与 p−1、q−1 没有公因子（common factor）。标准说法只要求 gcd(e, φ) = 1，考试按老师的三条写。
    • 往年原题：为什么 2 永远不能当公钥（public key）？除 2 以外的素数（prime number）都是奇数，减 1 后是偶数，所以 2 一定是 p−1、q−1 的公因子（common factor），不满足第 ③ 条。
    • 求 d 用 k 法：d = (kφ + 1)/e，k = 1, 2, 3… 直到整除。老师建议考试就用这个方法，省时间。
    • 典型 15 分题：为什么 e ≠ 2 → 求 n、φ → 选 e、求 d → 给 M，加密（encryption）再解密（decryption）验证。课上的练习：p=5, q=11 自选密钥（key）；p=17, q=19, e=5, M=25；p=13, q=23, e=7。

    加密（encryption）和解密（decryption）

    公式

    加密（encryption）（用接收方公钥（public key））：C = Me mod n　　　解密（decryption）（用自己的私钥（private key））：M = Cd mod n

    要求：明文（plaintext） M 必须小于 n。

    例（P4-72）：加密（encryption） “DC”。按 A = 0, B = 1, C = 2, D = 3… 编码，DC → 32。

    RSA 的概念题（Q&A Q24、Q29）

    • 单向函数（one-way function）：C = Me mod n，已知 M 和 e 算 C 很容易；已知 C 和 e，n 很大时反推 M 很难；
    • 陷门（trapdoor）：私钥（private key） d，掌握它就能轻松反推，M = Cd mod n；
    • 公钥（public key） e（连同 n），私钥（private key） d；
    • 安全性主要取决于分解（factorization） n 的难度；n 很大、e 选得合适，系统就是安全的；
    • p 和 q 能公开吗？不能。知道 p、q 就能算出 φ，有了 φ 就能由 e 算出 d。反过来，知道 n 和 φ 也能解出 p、q。所以 p、q、φ、d 都要保密，只公开 n 和 e。

    RSA 中 p = 3，q = 11，e = 7，私钥（private key） d 是多少？

    φ = 2 × 10 = 20。k = 1：(20 + 1) ÷ 7 = 3 ✓，所以 d = 3（课件 P4-76）。验证：7 × 3 = 21 = 20 + 1。

    RSA 的安全性依赖于？

    RSA 依赖分解（factorization）；DH 和 ElGamal 依赖离散对数（discrete logarithm）。这一对常被拿来对比出题。

    10哈希（hash）：给数据按一个“指纹（fingerprint）”

    本节用 红圈 圈出的是 quiz 和期末最常考的结论，考前至少把圈出来的背熟。

    前面讲的加密（encryption）都是为了保密：别人看不懂，但自己能解回来。这一节的哈希（hash）目的完全不同：它不让人看不懂，而是让人发现数据有没有被改过。

    Hash function（哈希函数）把任意长度的数据压缩成一串固定长度的“摘要”（digest）。它是单向（one-way）的：从摘要无法还原原文。课件称它为 “a special mathematical function that performs one-way encryption”，答案是 Hashing（样题 Q4-33）。

    类比

    就像人的指纹（fingerprint）：从一个人很容易得到他的指纹（fingerprint），但只看指纹（fingerprint）没法“复原”出这个人；两个人指纹（fingerprint）相同几乎不可能。Q&A Q31 用的类比是软件包装盒上的防拆封条（tamper-evident seal）：盒子被打开过（文件被改过），一眼就能看出来。

    看几个真实的 SHA-256 摘要（digest）

    SHA-256 不管输入多长，输出永远是 256 位，写成 64 个十六进制字符：

    SHA-256("hello") = 2cf24dba5fb0a30e…1fa7425e73043362938b9824 SHA-256("Hello") = 185f8db32271fe25…a518007d1764826381969 SHA-256(一个 10 MB 的文件) = 0c9a42b3d065a640…7bc7973a421a964a11304c998c

    三个现象正好对应哈希（hash）的性质：① 5 个字母和 10 MB 的文件，输出一样长；② “hello” 只把 h 改成大写，256 位里有 125 位变了（接近一半），这就是雪崩效应（avalanche effect）；③ 同样的输入每次算出来都一样（确定性），所以才能拿来比对。

    哈希（hash）的性质（P4-108）

    性质意思防的是什么
    固定长度、计算快任意大小的输入，输出长度固定，算起来很快—（实用前提）
    单向（one-way）（抗原像（preimage resistance））给定摘要（digest） h，找不到 x 使 H(x) = h从数据库（database）里偷到密码（password）哈希（hash），也反推不出密码（password）
    弱抗碰撞（weak collision resistance）（抗第二原像）给定一个 x，找不到另一个 y ≠ x 使 H(y) = H(x)攻击者（attacker）造一个摘要（digest）相同的假文件替换真文件
    强抗碰撞（strong collision resistance）找不到任意一对 x ≠ y 使 H(x) = H(y)攻击者（attacker）事先准备一真一假两份合同，让你签真的、他拿假的
    雪崩效应（avalanche effect）输入改一个字母，输出完全变样（P4-111）没法通过“输出差不多”去猜输入
    易错点：弱抗碰撞（weak collision resistance） vs 强抗碰撞（strong collision resistance）

    区别在x 是不是给定的。弱：题目先给你一个 x，让你找和它撞车的 y（更难）；强：x、y 都随你挑，只要撞车就行（更容易做到，所以要求更高）。碰撞（collision）在数学上一定存在（无限多的输入挤进有限的输出），安全的意思是“找不到”。SHA-256 有 2256 种输出，按生日悖论，随便找一对碰撞（collision）也要大约 2128 次计算。

    哈希用在哪：三个例子

    例 1：检查下载的文件有没有被改

    软件官网在下载链接旁边公布安装包的 SHA-256。你下载完自己算一遍，和官网的对比：一样，说明文（plaintext）件完整；哪怕被插进 1 个字节（byte）的病毒（virus），摘要（digest）也会完全不同。这就是哈希（hash）的本职：完整性（integrity）。

    例 2：网站怎么存你的密码（password）

    网站不存密码（password）本身，只存密码（password）的哈希（hash）。你设密码（password） 123456，数据库（database）里存的是 8d969eef6ecad3c2…；登录时把你输入的密码（password）再算一次哈希（hash），和存的比对，一样就放行。这样数据库（database）被偷了，黑客（hacker）拿到的也只是摘要（digest）。所以能“找回原密码（password）”的网站说明没用哈希（hash），不安全；正常只能重置。

    但像 123456 这种常用密码（password），攻击者（attacker）可以提前把常见密码（password）的哈希（hash）都算好（彩虹表（rainbow table）），一查就知道。所以实际中每个用户再加一段随机的盐（salt）一起哈希（hash），同样的 123456 存出来也各不相同。

    例 3：数字签名（digital signature）先哈希（hash）再签

    一份 100 页的合同直接用 RSA 签名（signature）太慢，所以先算出 256 位的摘要（digest），再用私钥（private key）只签这个摘要（digest）。接收方重新算一遍摘要（digest），和解开的签名（signature）比对，相等就说明没被改过、也确实是对方签的（下一节详细讲，样题 Q4-28、Q4-30）。

    哈希（hash）单独用为什么不能认证（authentication）：哈希（hash）人人都会算，没有密钥（key）。攻击者（attacker）把文件改了，顺手把旁边的摘要（digest）也换成新算的，你根本发现不了。要证明“是谁发的”，必须加入密钥（key）：要么用共享密钥（shared key）做 MAC/HMAC（带密钥的哈希（keyed hash）），要么用私钥（private key）签名（signature）做数字签名（digital signature）。

    哈希（hash） ≠ 加密（Q&A Q31）

    加密（encryption）哈希（hash）
    输出长度和明文（plaintext）差不多，或更长固定且短，与输入长度无关
    能还原吗能（解密（decryption））不能（不能 de-hash）
    需要密钥（key）吗需要不需要
    目的机密性（confidentiality）完整性（integrity）（样题 Q4-26）

    哈希函数（hash function）的主要目的是？（样题 Q4-26）

    哈希（hash）本身没有密钥（key），单独使用证明不了是谁发的，所以主要用于完整性（integrity）。和私钥（private key）签名（signature）结合后才能提供认证（authentication），那是下一节的内容。

    老师课上强调 · W8

    样题 Q4-26：哈希（hash）的主要目的？只有 data integrity，不提供 authentication，认证要靠数字签名（digital signature）。Q4-27：SHA 是算法，hash value 和 digest 都是输出。

    攻击者（attacker）想事先准备好一真一假两份合同，让它们的摘要（digest）相同，再骗你签真的那份。这需要破坏哈希（hash）的哪个性质？

    两份都由攻击者（attacker）自己挑，只要求“任意一对撞车”，这是强抗碰撞（strong collision resistance）。如果是你给定一份文件、他去找另一份撞车，那是弱抗碰撞（weak collision resistance）。

    考点清单（必背）
    • 哈希（hash）的主要目的：只有完整性（data integrity），不提供认证（authentication）、不提供保密。
    • “one-way encryption” 的数学函数 = Hashing；哈希不能还原，不需要密钥（key）。
    • 输出固定长度；性质：单向（one-way）、弱抗碰撞（weak collision resistance）、强抗碰撞（strong collision resistance）、雪崩效应（avalanche effect）。
    • 最广泛使用的家族：SHA；MD5、SHA-1 已不安全；SHA-1 是 160 位（老师口误说成 168）。
    • SHA 是算法，hash value / digest 是输出。
    • 密码（password）存哈希；能找回原密码（password）的网站不安全。
    • 数字签名（digital signature）：用发送方私钥（private key）签摘要（digest），用发送方公钥（public key）验证，两个摘要（digest）相等即通过（下一节）。

    11数字签名（digital signature）：证明“这是我发的，而且没被改过”

    手写签名（handwritten signature）容易伪造（forgery），靠和真迹比对来验证；数字签名（digital signature）很难伪造（forgery），用公开的算法验证（P4-103）。它就是把公钥加密（public-key encryption）“反过来用”：发送方用自己的私钥（private key）处理消息的哈希（hash）（样题 Q4-28、Q4-31）。

    签名（signature）提供什么、不提供什么

    • ✓ 完整性（integrity）：消息改一个字，哈希（hash）就对不上；
    • ✓ 认证（authentication）：只有 Bob 有私钥（private key），能用他的公钥（public key）解开，就证明是他签的；
    • ✓ 不可否认（non-repudiation）：Bob 事后不能说“不是我”；
    • ✗ 不提供机密性（confidentiality）：消息本身是明文（plaintext）发送的。如果还需要保密，就再用 Alice 的公钥加密（public-key encryption）整条消息，这就是课件 P4-113 的“with message protection”。

    样题 Q4-29：签名（signature）能保证 integrity 和 source，选 Both；Q4-30：哈希值（hash value）相等说明没有被篡改（tampering）。

    RSA 签名（signature）小例子（P4-117）

    沿用 n = 55，e = 3，d = 27。签名（signature） M = 51：S = 5127 mod 55 = 6（用私钥（private key） d）。验证：63 mod 55 = 216 mod 55 = 51 = M ✓（用公钥（public key） e）。和加密（encryption）正好反过来。

    发送方给哈希（hash）做数字签名（digital signature），用的是哪把钥匙？

    签名（signature）用自己的私钥（private key），验签（signature verification）用对方的公钥（public key）。

    老师课上强调 · W7

    期末手算签名（signature）不用哈希（hash）（哈希（hash）需要电脑）：签名（signature） S = Md mod n（用私钥（private key）），验证 Se mod n = M（用公钥（public key）），和 RSA 加密（encryption）正好相反。课上的例子：p=5, q=11, e=3, d=27, M=51 → S = 6，验证 63 mod 55 = 51 ✓。

    12数字证书（digital certificate）与 CA：怎么确定这把公钥（public key）真是 Bob 的

    还有一个漏洞（vulnerability）：Alice 怎么知道手里的“Bob 公钥（public key）”真的是 Bob 的？如果 Eve 冒充（masquerading） Bob 发来她自己的公钥（public key），Alice 用它去验证 Eve 伪造（forgery）的签名（signature），当然“验证通过”（P4-118：不能用发送方自己提供的公钥（public key））。这正是公钥密码（public-key cryptography）的核心难题：证明一把公钥（public key）确实属于某人（P4-47）。

    类比

    陌生人说“我是张三”，你不信；他拿出政府签发的身份证，你就信了，因为你信任政府。数字证书（digital certificate）就是公钥（public key）的“身份证”，CA（证书颁发机构）就是“发证的政府”。

    Digital certificate：由 CA 签发并数字签名（digital signature）的电子文件，把用户名字和他的公钥（public key）绑定在一起（样题 Q4-25）。它的作用是认证（authentication）公钥（public key）（样题 Q4-32），私钥（private key）永远不会出现在证书（certificate）里。

    X.509 证书（certificate）里有什么（P4-120、P4-121）

    字段含义
    VersionX.509 版本（大多是 v3）

    Serial number唯一序列号，用来查询是否被吊销（revocation）

    验证证书（certificate）的三件事（P4-122；Q&A Q33，必背）

    1. 签名（signature）：用 CA 众所周知的公钥（public key）验证证书（certificate）上的签名（signature），通过说明证书（certificate）是真的、没被改过；
    2. 有效期（validity period）：当前时间在证书（certificate）的有效期（validity period）内吗？过期的要拒绝；
    3. 吊销（revocation）：有效期（validity period）内 CA 也可能吊销（revocation）证书（certificate）。看证书（certificate）字段是看不出来的，必须向 CA 查询，例如用 OCSP：把序列号（serial number）发给 CA，CA 回答 good、revoked 或 unknown。
    现实的坑

    很多国家的 CA 没有监管，用户也能自己生成证书（certificate），所以公钥（public key）仍然可能被冒充（Q&A Q28）。只接受有信誉的 CA 签发的证书（certificate）。新加坡常见的 CA：Verisign、GlobalSign、Netrust。模块 6 的 Equifax 案例里，一张过期 10 个月的证书（certificate）导致数据外泄（data exfiltration）没被发现。

    验证数字证书（digital certificate）时，不需要检查哪一项？

    私钥（private key）从不出现在证书（certificate）里，也无从检查。三件事：签名（signature）、期限、吊销（revocation）。

    老师课上强调 · W8

    “这道题以前考过”：怎样验证证书（certificate）有效？① 用 CA 的公钥（public key）验证 CA 签名（signature），确认是可信的 CA；② 是否在有效期（validity period）内；③ 是否被吊销（revocation）。三项都通过，浏览器（browser）才接受。证书（certificate）已经在客户手里，CA 收不回来，只能把它的序列号（serial number）作废，这就是吊销（revocation）。

    13未来挑战与本章小结

    课件 P4-125 列出的挑战：密钥管理（key management）（生成、存储、分发）；量子计算（Shor 算法能破解 RSA 和 ECC）；同态加密（homomorphic encryption）（直接在密文（ciphertext）上计算）；为 IoT 设计的轻量级密码（lightweight cryptography）；安全与性能的权衡；淘汰过时算法（DES、MD5、SHA-1）。

    一页纸总结
    • 明文（plaintext） → 密文（ciphertext）是加密（encryption）；安全靠密钥（key）而不是靠算法保密；每多 1 位密钥（key），难度翻倍。
    • 对称（symmetric）：一把钥匙，快，难在密钥分发（key distribution）。Block（DES、AES）vs Stream（RC4）；ECB 各块独立，CBC 链式。
    • DES 64 / 56 / 16，1998 年 56 小时被破；2DES 有中间相遇攻击（meet-in-the-middle attack）；3DES 是过渡；AES 128 / (128, 192, 256) / (10, 12, 14)。
    • 公钥（public key）：保密用接收方公钥（public key），签名（signature）用发送方私钥（private key）；更安全是错误说法，它解决的是分发问题。
    • DH：只交换密钥（key），基于离散对数（discrete logarithm）；Y = aX mod q，K = Y对方X自己 mod q。
    • RSA：n = pq，φ = (p−1)(q−1)，e 与 φ 互素（relatively prime），d = (kφ + 1) / e；C = Me mod n，M = Cd mod n；基于大数分解（integer factorization）；p、q、φ 必须保密。
    • ECC 用更短的钥匙；等效强度（equivalent strength）：AES-128 ≈ ECC-256 ≈ RSA-3072。混合系统（hybrid system）：公钥（public key）送钥匙，对称（symmetric）加数据。
    • 哈希（hash）：固定长度、单向（one-way）、抗碰撞（collision resistance）、雪崩效应（avalanche effect）；用于完整性（integrity）；MD5 和 SHA-1 已淘汰。
    • 签名（signature） = 私钥（private key）处理哈希（hash） → 完整性（integrity） + 认证（authentication） + 不可否认（non-repudiation），没有机密性（confidentiality）；验签（signature verification）：比较两个摘要（digest）。
    • 证书（certificate）把名字和公钥（public key）绑定，由 CA 的私钥（private key）签名（signature）；验证三件事：签名（signature）、期限、吊销（OCSP）。
